# 근거 대응표 작성과 로컬 비교 실험 실시 기록

작성일: 2026-09-28

사용자의 실행 승인에 따라 근거 대응표와 로컬 생성·비교 프로그램을 구현하고 60문항 × 2조건 × 3회, 총 360개 요청을 수행했다. 모두 정상 응답했다. 답변 내용의 자동평가와 연구자 직접 근거 검토는 아직 진행하지 않았다.

## 자료와 근거 대응표

- 원본 PDF, 고정 corpus `corpus-v6-final`, BGE-M3 인덱스 `bge-m3-v1`, 기존 60문항을 유지했다.
- PDF 67쪽에서 필요한 사실과 대체 근거를 대조했다. 단일 근거 20개, 다중 근거 30개, 답변불가 10개의 질문 문구와 유형은 그대로다.
- 각 근거의 충분 청크 조합을 AND/OR로 기록했다. S16처럼 원문 근거 하나가 두 청크에 걸치는 경우에는 두 청크를 함께 요구한다. 답변가능 문항의 최소 충분 청크 수는 최대 3개다.
- 수치·단위·적용 조건, 원문 자체의 절 번호와 표기 차이를 채점 주석으로 남겼다. 원문을 임의로 고치거나 검색 결과에 맞추어 정답을 변경하지 않았다.
- 답변불가 10개는 관련 정보가 전혀 없다는 뜻이 아니다. 질문이 요구하는 전체 절차 등이 제1·2장 corpus에 충분히 없는 경우이며, 알려진 부분과 부족한 부분을 구별해 기록했다.

상세 자료: [근거 대응표](../experiment/gold-v1/대응표.md), [기계 검증과 대조 범위](../experiment/gold-v1/validation.json).

연구자 직접 확인은 `PENDING`이다. Codex의 원문 대조를 연구자 또는 정비 전문가의 확인으로 간주하지 않는다. 아래 검색 점수는 현재 근거표에 따른 잠정 결과다.

## 고정한 실행 방법

| 항목 | 실제 실행 |

| 생성 모델 | Qwen3-4B-Instruct-2507, Q4_K_M GGUF |

| 실행기 | Ollama 0.34.1, 실험 전용 127.0.0.1:11435 |

| 정보 분리 | 정답·문항 유형·답변가능 여부는 생성 모델에 전달하지 않음 |

| 품질 분석 대상 | 첫 회차의 120개 답변. 후속 회차의 더 좋은 답변으로 대체하지 않음 |

GGUF는 Qwen 공식 배포 파일이 아닌 제3자 양자화본이다. 게시된 LFS SHA-256과 다운로드 바이트의 일치를 확인했다. 모델·tokenizer·코드·설정·문항 해시는 [실행 manifest](../experiment/runs/formal-v1/manifest.json)에 남겼다.

개발 단계에서는 공통 프롬프트를 수정했다. 초기 버전에서 LLM Only가 10개 모두 유보했고, 대상 차량·교범도 알려주지 않았기 때문이다. 두 조건 모두에 같은 차량·교범명을 넣고, 발췌가 없으면 기존 모델 지식으로 답하도록 명확히 했다. 최종 문항의 답변을 생성하기 전에 수정했다. 초기 개발 D04의 오일 종류는 최종 M15의 필수 사실 일부와 겹쳐 다른 질문으로 교체했다. 이전 설정과 결과는 삭제하지 않았다. 상세 사유는 [결정 기록 E06~E08](../experiment/DECISIONS.md)을 따른다.

## 검색 결과

질의별 근거 Recall@5를 먼저 계산한 뒤 문항 평균을 냈다. 답변불가 10개는 이 검색 지표에서 제외한다.

| 유형 | 문항 수 | Evidence Recall@5 평균 | 모든 필수 근거 검색 |
| --- | ---: | ---: | ---: |
| 단일 근거 | 20 | 0.8500 | 17/20 (85.0%) |
| 다중 근거 | 30 | 0.5833 | 9/30 (30.0%) |
| 답변가능 전체 | 50 | 0.6900 | 26/50 (52.0%) |

다중 근거 문항에서는 일부 근거만 검색된 경우가 많았다. 생성답변이 그 근거를 올바르게 사용했는지, 필요한 내용을 충분히 답했는지는 별도의 평가로 확인해야 한다.

## 시간과 자원

두 조건 모두 세 회차 정상 응답한 공통 60문항을 사용했다. 표의 시간은 **질의별 3회 중앙값의 median/p95**다. 한 요청이 약 23초 걸린 경우도 삭제하지 않았다. 해당 요청의 시간은 주로 모델 입력 처리에서 발생했으며 원인을 단정하지 않았다.

| 조건 | median (초) | p95 (초) | Peak RSS (GiB) | Peak 장치 VRAM (GiB) |
| --- | ---: | ---: | ---: | ---: |
| LLM Only | 2.231 | 4.478 | 8.927 | 4.612 |
| RAG | 1.754 | 3.155 | 12.708 | 4.592 |

RAG 검색 시간의 질의별 대표값 중앙값은 약 0.112초다. 첫 회차 답변의 평균 출력 길이는 LLM Only 약 160.5 token, RAG 약 91.8 token이었다. 두 조건의 답변 길이가 달라, 응답시간 차이만으로 RAG의 계산 효율이 더 높다고 결론내릴 수는 없다.

RSS는 필요한 프로세스의 working set 합계로 공유 메모리의 중복 가능성이 있다. 생성 프로세스의 RSS가 모델 파일 크기보다 컸으며 측정값을 그대로 보고했다. 장치 VRAM은 운영체제와 다른 상주 프로그램의 사용량도 포함한다. 양쪽 조건 각각 180개 요청의 자원 표본이 유효했다. 표본 목표 간격은 100ms, 관측된 최대 간격은 LLM Only 약 115.5ms, RAG 약 122.1ms였다. 상주 상태에서 얻은 관측 최대값이며 샘플 사이 순간 최대값은 보장하지 않는다.

수집 종료 후 실험용 생성 모델을 메모리에서 해제했다. 결과 조회 서버와 기존 검색 앱은 계속 사용할 수 있다.

## 백업

작업 전 백업: `backups/before-experiment-20260928-124708/inputs.zip` 및 manifest. 2,181개 파일을 ZIP 항목별 SHA-256으로 검증했다.

작업 후 코드·근거표·모델 출처·실행 기록·평가 입력·이 문서는 별도의 실험 산출물 백업에 포함한다. 용량이 큰 모델 가중치와 기존 가상환경은 중복 저장하지 않고, 다운로드 해시·모델 출처·실행 환경 정보를 남긴다. 백업 위치와 검증 결과는 `experiment/reports/backup-after.json`을 따른다.
