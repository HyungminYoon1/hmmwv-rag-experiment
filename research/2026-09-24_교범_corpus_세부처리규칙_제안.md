# HMMWV 교범 corpus 세부 처리 규칙 제안

작성: 2026-09-24. 상태: **제안·미적용**. 기존 앱·청크·보정본에는 아직 적용하지 않았다.

기준은 「2026-09-24_corpus_생성과_청킹_구현계획」과 「2026-09-22_실험_정의와_처리규칙_v1.0」이다. 기존의 범위·500/100 설정은 유지하고, 아직 구체적이지 않은 원문 선택·표·읽기 순서의 판정 조건을 보완한다. 아래 수치와 예외 처리 기준은 이번 연구를 위한 제안이며, 외부 기관이 정한 보편적 표준이 아니다.

**1. 적용 범위와 현재 상태**

- 대상 PDF: `TM_9-2320-280-20-1_1996_Change2_2004_TFS_archive.pdf`. 전체 890쪽 중 PDF 순번 31~863쪽, 제1·2장 833쪽을 검색 범위로 유지한다. 이 문서의 쪽수는 모두 인쇄 쪽번호가 아닌 PDF 순번이다.
- 입력: v4 보정 레코드, 보정 목록, 557건 구간 판정, PMCS·표·읽기 순서 자료, 원시 추출 좌표. 기존 입력은 보존한다.
- 기준 결과: `corpus-20260924-044626-593182`, 구조단위 994개·청크 1,126개. 현재는 최종 검색 입력본이 아닌 후보 corpus다.
- 현재 검토 목록 2,189건에는 추출층 대응 818건, 본문 경계 676건, OCR 영역 구조 609건, 표 구조 14건, 미배정 문자 72건이 있다. 같은 페이지·구간에 여러 종류의 검토 항목이 생길 수 있다.
- 선택 기록의 보류 969구간은 추출층 대응 818, 규칙 충돌 79, 미배정 문자 72로 구성된다. 이는 서로 다른 원문 내용 969개가 전부 빠졌다는 뜻이 아니다. 대안 추출층이나 이미 다른 표현으로 포함된 구간도 있다.

**2. 원문 선택: 추출층 선택과 표 표현을 구별한다**

| 규칙 | 채택·처리 조건 | 검토를 남기는 조건 |
| --- | --- | --- |
| S01 기존 판정 재사용 | 557건의 판정은 기록된 페이지·구간·출처에만 적용한다. 입력 해시와 구간 문자열이 같아야 한다. | 입력이 달라졌거나 같은 내용의 선택에 관해 두 판정이 실제로 다르다. |
| S02 추출층과 표현 방식 분리 | 먼저 native/OCR 중 어떤 원문 문자를 채택할지 정한다. 다음으로 그 문자를 본문, 제목, 표 셀, 주석 중 어디에 표현할지 정한다. | 표현 대상으로 연결한 셀이 해당 원문을 실제로 담지 못한다. |
| S03 같은 위치의 중복 | 같은 PDF 영역의 대안 추출이고, 허용된 공백 정리 후 전체 내용이 대응될 때 하나만 검색 텍스트에 넣는다. 미채택 구간은 채택 구간 또는 여러 셀의 문자 위치에 연결한다. | 좌표만 겹치거나, 일부 문자열만 일치하거나, 남는 문자에 설명이 없다. |
| S04 OCR 고유 본문 | native에 없는 이미지 내부의 설명·표 문자는 별도 영역으로 보존한다. 원문 대조와 구조 판정이 끝난 OCR에 기존의 확인을 재사용한다. | 영역이 다른 본문·그림·표를 함께 묶었거나 읽기 순서가 불명확하다. |
| S05 반복 문구 | 서로 다른 정비항목에 쓰인 경고·조건은 각 항목에 유지한다. | 같은 문자열이라는 이유만으로 다른 위치의 내용을 삭제하려 한다. |

S02는 현재 PMCS의 규칙 충돌을 처리하는 데 필요하다. 충돌 79구간은 모두 PMCS 페이지에 있으며, 표본에는 `native 채택`과 `표 셀에 표현`이 서로 다른 상태라는 이유로 충돌한 사례가 있다. 두 판단은 함께 성립할 수 있다. 다만 79건을 일괄 해제하지 않고, 각 native 구간 전체가 지정된 셀의 문자와 대응하는지 검사한 뒤 처리한다.

S03의 대응 기록은 "이 영역은 중복"이라는 표시에서 끝나지 않는다. 미채택 구간의 모든 문자를 어느 채택 구간이 대신하는지, 공백 등의 차이는 어떤 규칙에 의한 것인지 남긴다. 표 영역 안에 들어왔다는 이유만으로 native나 OCR을 전부 버리지 않는다.

**3. 비교용 정리와 문자 수정의 경계**

현재 선택 코드의 `compact()`는 대소문자를 통일하고 비단어 문자를 제거하며, 일부 구간에는 유사도 0.8을 중복 판단에 사용한다. 이것만으로 정비교범의 동등성을 확정하지 않도록 수정하는 것을 제안한다.

- S06: 자동 동등성 비교에는 줄바꿈 방식 통일, NBSP의 일반 공백 치환, 연속 공백의 단일 공백 치환만 기본 허용한다. 공백을 모두 삭제하지 않는다. 비교용 문자열과 실제 저장 문자열을 구별한다.
- S07: 숫자, 소수점, 부호, 범위 기호, 단위, 부품·차종·오류 코드, 핀 문자의 대소문자, 부정·제한 표현은 보존한다. 예를 들어 `12.0`과 `120`, `j`와 `J`, `O`와 `0`, `ON`과 `OFF`를 동등하다고 처리하지 않는다.
- S08: 줄끝 하이픈이나 낱말 내부 공백의 결합은 원문에서 확인된 구간 규칙 또는 보정 목록이 있을 때만 적용한다. 차종명·범위·부품번호의 하이픈은 줄바꿈용 하이픈과 구별한다.
- S09: 유사도와 좌표 겹침은 대조할 후보를 찾는 데 사용한다. 최종 채택·중복 해제의 근거는 전체 문자 대응과 확인된 구조 관계다. native가 있다는 이유나 OCR 신뢰도가 높다는 이유만으로 다른 추출층을 버리지 않는다.
- S10: 새 문자 오류는 다음 보정 배치에 원문 위치, 수정 전후, 사유를 기록한다. corpus 프로그램 안에서 철자나 수치를 별도로 고치지 않는다. PDF에도 존재하는 오탈자·불완전 문장은 추출 오류와 구별한다.

**4. 본문·제목·페이지 간 연결**

| 규칙 | 적용 방법 |
| --- | --- |
| B01 영역부터 구분 | 페이지 안의 본문, 표, 그림 설명, 진단 박스, 머리말·꼬리말을 구분한 뒤 각 영역 내부의 순서를 정한다. 페이지 전체를 y좌표→x좌표 순서로 단순 연결하지 않는다. |
| B02 제목 인식 | 절 번호, 제목 배치, 서체와 문서 계층을 함께 사용한다. `2-312 PCB` 같은 참조 쪽번호를 절 제목으로 채택하지 않는다. 애매한 제목은 확인한 규칙에 등록한다. |
| B03 여러 단 | 확인된 다단 본문은 단 내부에서 위→아래로 읽고 다음 단으로 이동한다. 좌우가 각각 참고 설명과 진단표인 페이지는 두 영역을 독립 처리한다. 흐름도에는 일반 다단 규칙을 적용하지 않는다. |
| B04 이어진 항목 | 절·항목·DTC 등 식별자가 일치하고, `Cont'd`나 원문 문장·표 연결이 확인되면 이어 붙인다. 단순히 다음 페이지이거나 제목이 비슷하다는 이유로 합치지 않는다. |
| B05 반복 제목 | 이어진 페이지의 같은 제목은 적용 맥락으로 연결하고 원문 위치를 보존한다. 짧은 독립 청크로 만들거나 의미 없는 문자로 누락시키지 않는다. 쪽번호·문서번호 등 순수 레이아웃 문자만 별도 제외한다. |
| B06 경고·주석 | 경고와 NOTE의 적용 대상 절·작업·행을 명시적으로 연결한다. 먼저 확인된 배치 규칙으로 범위를 정하고, 예외는 구간별로 지정한다. 경고가 가까이 있다는 이유만으로 옆 표나 다음 작업에 붙이지 않는다. |
| B07 절차 순서 | a/b/c, 1/2/3 등 절차 순서를 유지한다. 다른 작업의 같은 번호를 같은 절차로 묶지 않는다. 기존에 끊긴 문장을 추론하여 완성하지 않는다. |

적용 대상이 확인된 경고·조건은 관련 청크의 필수 맥락으로 반복한다. 적용 범위가 불분명한 경고를 임의로 축소하거나, 500 token에 맞추려고 삭제하지 않는다.

**5. 표의 공통 규칙**

1. T01: 표를 제목·상위 조건·행·열·셀·각주로 표현한다. 표 식별자는 표 번호만 쓰지 않고 장·절과 시작 페이지를 포함한다. 다른 위치의 `Table 2-1`을 같은 표로 오인하지 않는다.
2. T02: 각 셀은 행 식별자와 열 제목에 연결한다. 셀 좌표와 확인된 행 경계를 사용하며, 따로 추출한 열 목록의 순번을 단순히 맞춰 행을 만들지 않는다.
3. T03: 차종, 엔진·변속기 형식, 작동 상태, 단위, 검사 간격 등 상위 조건은 해당하는 하위 행에 복사하고 원문 참조를 남긴다. 같은 페이지의 모든 행에 일괄 적용하지 않는다.
4. T04: 값이 비어 있으면 빈 셀로 보존한다. 빈칸을 `No`, `0`, `해당 없음`으로 바꾸지 않는다. 병합 셀이나 페이지 간 연속 관계가 원문에서 확인된 경우에만 상위 값을 상속한다.
5. T05: STANDARD/METRIC, 정상 조건/임무수행 불가 조건처럼 의미가 다른 열을 분리한다. 값만 나열하지 않고 원문의 열 이름·조건과 묶어 검색 텍스트에 넣는다.
6. T06: PMCS는 항목 번호·간격·점검 대상·절차·임무수행 불가 조건을 연결한다. 페이지를 넘는 같은 항목은 연결하되, 서로 다른 항목은 합치지 않는다. a/b/c별 절차와 판정의 대응은 원문에서 확인된 경우에만 추가한다.
7. T07: 독립적으로 이해되는 행·하위 절차를 구조단위로 삼는다. 행 하나가 독립적으로 이해되지 않으면 필요한 상위 행·조건을 연결한다. 긴 셀을 나눈 모든 청크에도 행 식별자·열 이름·필수 조건이 남아야 한다.
8. T08: 표 안의 각주 표시는 각주 본문과 연결한다. 표 밖 그림의 캡션·화살표 문자를 표의 추가 열로 집어넣지 않는다.

직렬화는 원문 값에 열 이름·구분자를 붙이는 방식으로 한다. 열 이름과 구분자도 출처 또는 생성 유형을 기록한다. LLM이 표를 자연스러운 문장으로 다시 쓰는 과정은 넣지 않는다.

| 329 | OFF/RUN/START, PCB/Distribution Box, 엔진 상태로 나뉜 7개 조건 묶음을 유지한다. 왼쪽 참고·경고와 오른쪽 진단표를 별도 영역으로 처리하고 적용 관계를 확인한다. |
| 532 | 위쪽은 Ignition ON·Engine OFF, 아래쪽은 Ignition ON·Engine ON 조건이다. 두 표 5행·4행, 핀 문자의 대소문자, 위쪽의 제어기 분리와 아래쪽의 재연결·PARK 조건을 유지한다. 오른쪽 `No`는 측정값 열이 아닌 분기 표기다. |
| 855 | Prompting Messages 5행과 Error Readouts 14행을 별도 표로 만든다. 코드·설명의 대응을 유지하며 기존 원문 이상 기록을 함께 연결한다. 애매한 코드 문자를 기대하는 철자로 자동 수정하지 않는다. |

532쪽의 기존 검토 기록에 쓰인 ‘시동 OFF/ON’은 정확한 구분이 아니다. 이번 원문 대조에서 **두 표 모두 Ignition ON이며 Engine OFF/ON이 다른 조건**임을 확인했다. 실제 구현 때는 이 조건 설명을 새 버전의 구조 자료에 정확하게 반영해야 한다.

이미 구조화한 PMCS, 272·276쪽 압력 표, 531쪽 비율 표, 830쪽 검사 목록, 854쪽 상태 표, 856쪽 부품 목록도 같은 검사에 포함한다. 새로 발견한 표는 이 목록 밖이라는 이유로 건너뛰지 않고 별도 구조 규칙을 등록한다.

**7. 그림·흐름도·원문 자체의 이상**

- G01: 그림 안에 있는 독립 설명문·명시적인 표는 문자 내용과 구조가 확인되면 포함한다. 이미지 출신이라는 이유만으로 제외하지 않는다.
- G02: 흐름도의 각 진단 박스에 적힌 본문과 명시적 쪽 참조는 보존한다. 박스와 그림 영역을 식별하여, 옆에 있는 `Yes/No`나 화살표를 본문 뒤에 단순 연결하지 않는다.
- G03: 이번 텍스트 실험에서는 화살표 경로·배선·부품 위치의 새로운 해석을 본문으로 생성하지 않는다. 그런 관계는 PDF 위치와 그림 의존 여부로 기록한다. 같은 영역에서 문자만으로 성립하는 문장까지 함께 제외하지 않는다.
- G04: PDF 118쪽의 `Metal particles are`처럼 원문 자체가 불완전한 문장은 그대로 보존하고 해당 구간을 표시한다. 문장의 결론을 추가하지 않는다. 같은 페이지의 완결된 다른 지시문은 정상적으로 처리한다.
- G05: 98쪽의 `Belt`는 PDF에서도 INTERVAL 열 안에 배치되어 있다. 추출 위치의 오류로 간주하여 다른 열로 옮기지 않고 원문 배치 이상을 기록한다.
- G06: 원문에 이상이 있음을 확인한 사례와 아직 원문을 판독하지 못한 사례를 구별한다. 판독이 끝나지 않은 문자를 ‘원문 문제’라고 이름만 바꾸어 검토 완료 처리하지 않는다.

원문 자체의 이상은 별도 목록에 남기므로 corpus의 구조 처리가 끝나도 0건이 될 필요는 없다. 반면 채택할 문자나 연결 관계를 아직 정하지 못한 경우는 미결로 남는다.

**8. 구조를 정한 뒤 적용할 청킹 규칙**

기존 Qwen3-4B-Instruct-2507 tokenizer의 고정 revision·파일 해시와 아래 방식을 유지한다.

1. 제목·표 머리글·필수 조건을 포함한 최종 검색 문자열 전체에 500 token 상한을 적용한다. 500으로 채우기 위해 다른 정비항목을 합치지 않는다.
2. 구조단위가 500 이하면 하나의 청크로 둔다. 넘으면 같은 단위의 본문을 현재의 token 창 방식으로 나눈다.
3. 같은 구조단위의 인접 창에 본문 100 token을 중첩한다. 문자 경계를 지키기 위해 정확히 100이 안 되면 100 이상인 가장 짧은 문자 구간을 쓰고 실제 수를 기록한다. 제목·조건 반복은 본문 중첩에 포함하지 않는다.
4. 서로 다른 구조단위 사이에는 중첩하지 않는다. 문자 보존·필수 맥락·500 제한·새 본문 진행을 동시에 만족하지 못하면 검토 대상으로 남긴다.
5. 이번 보완에서 문장 기반 청커로 교체하거나 500/100을 최적화하지 않는다. 변경된 구조 때문에 총 청크 수는 1,126개와 달라질 수 있다.

**9. 누락·잘못된 연결의 검증 규칙**

| 검사 | 구체적인 통과 기준 |
| --- | --- |
| V01 범위 | 833쪽 모두에 텍스트·이미지 영역 처리 기록이 있다. 인접 영역을 누락한 채 페이지 대표 기록 하나로 완료 처리하지 않는다. |
| V02 채택 문자 | 채택한 모든 본문·셀·제목·조건 구간이 청크 본문 또는 반복 맥락에 대응한다. 허용된 형식 정리 외에 설명되지 않는 누락·추가가 0이다. |
| V03 대안 추출 | 중복으로 제외한 구간은 대신 채택한 원문 구간에 전체 대응한다. 반복 경고를 삭제한 사례, 부분 일치 때문에 나머지 문자를 버린 사례가 0이다. |
| V04 표와 연결 | 원문 대조로 정한 행·열·셀 목록을 출력과 비교한다. 값→행→열→적용 조건의 연결이 일치하고, 숫자·부정·단위·식별자가 해당 셀에서 보존된다. 전체 문자 수만 맞는 것으로 대신하지 않는다. |
| V05 순서·경계 | 절차의 순번, 단의 순서, 페이지 연속 관계가 지정한 구조 규칙과 일치한다. 경고·조건이 다음 작업으로 넘어간 경우가 0이다. |
| V06 청크 | 모든 검색 문자열이 500 이하이며, 같은 단위 안의 본문 중첩·새 본문 진행·문자 매핑이 맞는다. 독립 단위 사이의 잘못된 중첩이 없다. |
| V07 미결 | 미해결 문자 선택·구조 판정이 0이다. 각 해제 항목에 적용 규칙·출처·검증 결과가 있다. 이유 없는 일괄 해제나 미추출 본문의 제외 처리는 허용하지 않는다. |
| V08 재현 | 같은 입력·규칙·환경에서 두 번 생성한 corpus·청크·선택 기록·출처 매핑의 해시가 일치한다. 실행시각은 비교 대상 데이터와 분리한다. |

V04의 기준 목록도 생성 코드가 자기 출력에서 만들면 독립 검증이 되지 않는다. PDF에서 확인한 표 구조·항목 목록을 별도 입력으로 고정하고 검사 프로그램이 다시 읽어 비교한다.

원문 대조는 다음 순서로 진행할 것을 제안한다.

1. 현재 미확정 표 14쪽은 모든 행·셀·조건을 대조한다. 확인된 표라도 새로 바뀐 연결이나 예외가 있으면 해당 부분을 대조한다.
2. 숫자·단위·부정·식별자 차이, 규칙 충돌, 제목·페이지 연속 관계가 불명확한 구간은 하나씩 판정한다. 자동 문자 대응으로 해제할 수 있는 항목은 대응 근거를 검증기가 확인한다.
3. 일반 본문·다단 본문·이미지 내 본문·표가 아닌 진단 박스 등 같은 구조의 페이지는 유형별 규칙을 먼저 만든다. 규칙 작성에 쓰지 않은 페이지를 유형별 최대 5쪽 선정하여 첫·마지막 쪽과 나머지 쪽을 확인한다. 나머지 표본은 `HMMWV-corpus-rules-v2|유형ID|PDF쪽번호4자리`를 UTF-8로 인코딩한 SHA-256의 오름차순으로 선택한다. 첫·마지막 쪽과 중복되는 후보는 제외하고, 동률이면 PDF 쪽번호가 작은 쪽을 먼저 쓴다. 유형 ID와 선정 목록을 입력 자료로 고정한다. 이는 이번 연구의 최소 점검안이며 통계적인 무오류 보증이 아니다.
4. 표본에서 오류가 나오면 같은 규칙이 적용된 전체 구간을 재검사하고 규칙을 고친다. 이미 확인한 표본을 통과하는 것으로 끝내지 않고 추가 표본도 확인한다.
5. 최종 평가질의를 고정할 때 모든 필수 근거를 PDF와 확인한다. 평가질의에 등장하는 부분만 우선 채택하거나 검색 점수를 보고 청킹 규칙을 바꾸지 않는다.

기계 검사는 누락·문자 변경·정해진 관계의 위반을 검출한다. PDF의 관계를 처음 정하는 과정에는 원문 대조가 필요하다. Codex의 원문 대조와 연구자의 직접 확인 여부는 별도로 기록한다.

**10. 구현 순서와 남길 자료**

1. 기존 후보 corpus와 입력 해시를 보존한다.
2. 추출층 선택·표현 방식·구조 역할을 구별하도록 선택 기록을 보완한다. PMCS 79구간과 중복 판정부터 다시 검증한다.
3. 818건 추출층 대응, 72건 미배정 문자 및 본문·OCR 구조 검토에 S/B 규칙을 적용한다. 각 검토 항목은 처리 구간과 규칙 ID에 연결한다.
4. 표 14쪽과 본문·진단 영역을 T/G 규칙으로 구조화한다. 532쪽 조건 설명도 이때 새 구조 자료에 반영한다.
5. 새 버전으로 청킹하고 V01~V08을 검사한다. 기존 청크와의 대응은 순번만이 아닌 원문 구간으로 계산한다.
6. corpus 버전, 입력·규칙·코드 해시, 검토 기록, 미결·원문 이상 목록, 이전/이후 포함 범위와 연결 변경표를 함께 보존한다. 실험용 corpus 고정 후 임베딩·검색 단계로 진행한다.

규칙을 프로그램에 적용한 뒤 다시 실행하는 과정에는 LLM을 호출하지 않는다. 원문 대조에서 판단한 선택·구조·문자 보정 내용을 명시적인 입력으로 저장하므로 같은 입력으로 재현할 수 있다.

**11. 설계 근거와 검토 범위**

- [기존 구현 계획](<2026-09-24_corpus_생성과_청킹_구현계획.md>): 구조를 먼저 정하고 길이를 제한하며 출처를 보존하는 기존 원칙과 500/100 정의를 유지했다.
- [기존 실험 정의](<2026-09-22_실험_정의와_처리규칙_v1.0.md>): 범위·평가질의 고정·전처리 변경 기록의 기준이다.
- [Docling 공식 청킹 설명](https://docling-project.github.io/docling/concepts/chunking/): 계층 기반 분할, token 제한, 표 머리글 반복과 같은 구조 보존 접근의 참고 자료다. 이 문서의 추출층 동등성 규칙·교범 예외·검토 표본 수·500/100의 최적성을 보증하는 출처는 아니다.
- [구현 코드](<../preprocessing/corpus>): 선택·구조·청킹·매핑·검증 관련 모듈과 기존 결정 기록을 검토했다. 앱 전체의 신규 동작 검증을 수행한 것은 아니다.
- [기존 구조 검토 자료](<../preprocessing/review-557/verified-v4-a>): 표 분류·원문 이상·557건 판정·PMCS 및 읽기 순서 자료를 사용했다. 큰 JSONL 자료는 현재 문제에 해당하는 레코드를 선택해 대조했다.
- [현재 후보 결과](<../preprocessing/output/corpus-20260924-044626-593182>): 상태·선택 기록·검토 사유를 확인했다. 이번 제안 작성 중 새 corpus를 생성하지 않았다.
- [PDF 대조용 렌더 기록](<evidence/corpus-detail-rules-proposal-2026-09-24/render-manifest.json>): 이번에 직접 화면 대조한 6쪽의 PNG와 해시를 기록했다. 전체 833쪽을 이번에 다시 시각 검토한 것은 아니다.

검토 범위 표기: 기준 Markdown 문서와 직접 관련 구현 모듈은 VERIFIED. 대용량 추출·구조 자료 및 원본 PDF는 PARTIAL로서 위의 선택 범위를 확인했다. 이전 단계에서 확인한 실험 기준을 적용했다.
