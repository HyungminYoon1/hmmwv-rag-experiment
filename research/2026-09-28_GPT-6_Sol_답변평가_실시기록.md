# GPT-6 Sol 답변 평가 실시 기록

작성일: 2026-09-28. 자동평가와 수치 검증 완료. 최종 집계는 `experiment/evaluation/runs/sol-formal-20260928-numeric-v3/summary.json`에서 확인한다.

## 대상과 설정

사용자가 선택한 GPT-6 Sol에 Windows 사용자 환경 변수의 API 키로 연결했다. 키 값은 출력하거나 파일에 저장하지 않았다. 공식 OpenAI Responses API에서 실제 응답을 받았으며 반환 모델명은 `gpt-6-sol`이다. reasoning effort는 medium, 요청별 출력 상한은 8,192토큰이다.

고정한 formal-v1의 첫 회차 120답변(60문항 × LLM Only/RAG)을 평가한다. 단일 근거 20문항, 다중 근거 30문항, 답변불가 10문항을 그대로 사용한다. 질문·정답 근거·검색 결과·원래 답변을 변경하지 않았다. 세 회차 360답변의 생성 시간 통계는 이 사후 평가시간과 구분한다.

평가 모델과 세부 프롬프트는 답변 생성 후 확정했다. 최종 평가 결과를 보고 문항·검색 설정·생성 모델을 조정하지 않는다. 지표의 상세 정의는 `experiment/evaluation/README.md`, 기존 연구 규칙은 `experiment/evaluation-policy.json`을 따른다.

## 실행 전 점검

- 가상 사례는 정답, 오답, 답변불가 3개이며 본 실험 집계에 포함하지 않는다.
- API 가상 사례 v1의 일시적 파일 교체 오류를 확인하여 저장만 제한적으로 재시도하도록 수정했다. 저장 실패가 유료 모델 재호출로 이어지지 않게 했다.
- 가상 사례 v3은 API 응답 17회로 3개 모두 정상 완료했다. 정답의 지지·요소·충실도는 1, 오답은 0, 답변불가 유보 판정은 1이었다. 관련 검사 32개를 통과했다.
- 가상 사례 v1·v2와 실패 이력, 변경 전 소스 백업을 보존했다.

## 관련성 수치 검산과 보정

실제 본 평가에서도 RAGAS의 관련성 점수와 독립 검산 간 차이가 발견됐다. 별도 재현 검사에서 입력 배열이 변하지 않았는데 NumPy dot 값이 달라지는 현상이 확인됐다. 다만 라이브러리·장치·런타임 중 구체적인 원인까지 확정한 것은 아니다. 스레드 수와 CPU 커널을 바꾼 진단만으로는 해결되지 않았다. 원래 실행은 불일치한 점수를 결측으로 보존한다.

수집 완료 후 저장된 최초 유효 역질문 3개, noncommittal 판정, BGE-M3 벡터로 관련성 점수를 다시 계산한다. 모든 답변 가능한 문항에 동일하게 적용하며, 모델을 재호출하거나 역질문을 바꾸지 않는다. Python math.fsum 기반 계산과 50자리 Decimal 계산이 1e-10 이내로 일치해야 한다. 원래 실행과 파생 실행을 분리하고 원본 파일·계산 코드의 해시와 변경 내역을 남긴다. 정답 근거 지지율·필수 요소 충족률·검색 문맥 충실도·유보 판정은 그대로 복사해 보존한다.

재계산 프로그램은 가상 사례에서 새 API 호출 없이 통과했다. 두 수치 구현의 최대 차이는 2.22e-16이었다. 수치 재계산과 별도의 검증 프로그램으로 원본 해시, 인용 존재, 주장 대응, 분모·평균·짝비교를 확인한다. 이 검사는 판정의 의미 정확성에 대한 사람의 검토를 대신하지 않는다.

## 본 평가 결과

자동평가 대상 120답변을 모두 처리했다. 최종 수치 집계는 `sol-formal-20260928-numeric-v3`를 사용한다. 사람이 확인하기 전의 자동평가 잠정치다.

| 지표 | LLM Only | RAG | 조건별 유효 답변 수 |
|---|---:|---:|---:|
| 질문 관련성 (−1~1) | 0.7267 | 0.8411 | 50 / 50 |
| 정답 근거 지지율 | 10.21% | 76.19% | 50 / 50 |
| 필수 요소 충족률 | 23.63% | 73.20% | 50 / 50 |
| 완전 답변유보율 | 8.00% | 4.00% | 50 / 50 |

RAG의 검색 문맥 충실도는 82.93% (50답변)다. 지지율·충족률·충실도는 답변별 비율의 평균이며, 전체 정답 문항 비율이 아니다.

답변불가 10문항에서는 RAG의 적절한 유보가 5/10, LLM Only의 교범 답변불가 유보가 4/10이었다. RAG는 부분 답변이 있을 때 정답 근거와 실제 검색 문맥 양쪽의 지지도 확인한다. 두 유보 지표의 판정 조건이 다르므로 동일한 정확도 지표로 취급하지 않는다.

답변 가능한 동일 50문항의 짝비교에서 RAG는 질문 관련성 +0.1144, 정답 근거 지지율 +65.99%p, 필수 요소 충족률 +49.57%p였다. 이 결과에서는 RAG가 근거 활용과 필수 정보 제공을 개선했으나, 답변불가 문항에서의 적절한 유보는 5/10에 그쳤다. 유의성 검정이나 정비 현장 적용 효과를 입증한 결과로 해석하지 않는다.

### 실행·검증 내역

- 원래 API 평가: 771응답. 유효 응답 770회, 인용 개수 불일치 1회는 미리 정한 재시도에서 정상 처리됐다.
- 원래 실행의 관련성 수치 검산 불일치 7답변은 원본에 그대로 보존했다. 추가 모델 호출 없이 답변 가능한 100답변 전체를 재계산했으며, 최종 집계에 남은 평가 오류는 0건이다.
- 일반 계산과 Decimal 50자리 계산의 최대 차이: 3.33e-16. 기존 지지·충족·충실·유보 판정은 변경하지 않았다.
- 원본·스냅샷 출처 해시 1,950개, 코드 16개, 주장-근거 판정 606건, 필수 요소 판정 248건, 관련성 계산 100건, 집계 항목 64개, 짝비교 12개를 프로그램으로 확인했다.
- 완료 실행의 재개 검사에서 새 모델 호출 0회, 기존 호출·결과 파일 1,661개 불변을 확인했다.
- 최초 파생 실행은 원본 집계 시각의 변경과 겹쳐 출처 검증에 실패했다. 집계와 계산 코드를 파생 실행 내 사본으로 고정한 뒤 검증했으며, 원본 집계를 다시 생성해도 최종 출처 검증이 통과했다. 이전 파생 결과도 삭제하지 않았다.

### API 사용량

본 평가 입력 576,746토큰, 출력 147,076토큰이다. 출력에는 추론 토큰 53,954개가 포함되어 있으므로 비용 계산에 다시 더하지 않는다. 캐시 입력은 0토큰이었다.

확인한 표준 요금(입력 100만 토큰당 $2, 출력 $10)의 단순 환산은 본 평가 약 $2.62, 가상 사례 API 점검 3회까지 합쳐 약 $2.71이다. 세금·계정별 조건·확정 청구서 금액은 확인하지 않았다. [공식 모델 요금](https://developers.openai.com/api/docs/models/gpt-6-sol).

## 남은 연구자 검토

정답 근거·대체 청크의 연구자 확인과 사전에 정한 40개 답변의 수동평가 대조는 아직 PENDING이다. 자동평가 점수를 정비 전문가의 검증 결과나 실제 정비업무의 정확도로 표현하지 않는다. 질문 관련성, 근거 지지율, 필수 요소 충족률은 각각 다른 측면을 측정하며 하나의 정답률로 합치지 않는다.
