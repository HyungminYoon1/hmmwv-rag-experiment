# 잔여 조건 연결과 OCR 혼합 구간 처리안

2026-09-24. 상태: **사용자 승인·부분 적용**. 네 쪽의 조건 연결 9건과 OCR 3쪽의 추가 보정, 혼합 후보가 있는 235쪽의 단어 좌표 확보 및 재생성·전후 비교를 마쳤다. 전체 OCR 구조 확대 검토는 아직 남아 있다. 적용 결과와 예외는 [실시 기록](../preprocessing/corpus/reports/잔여조건연결_OCR검토_실시기록_2026-09-24.md)에 기록했다. 아래 제안의 기준·계획·종료 조건은 당시 내용으로 보존하며, 적용하지 않은 부분까지 완료한 것으로 읽지 않는다.

제안 당시 기준은 `preprocessing/output/corrected-v6-a`, `preprocessing/output/corpus-v3-rules-c`, `preprocessing/corpus/rules/v3`였다. 적용 후 현재 기준은 `corrected-v7-a`, `corpus-v4-rules-c`, `rules/v4`다. 승인된 세부 규칙의 원문 보존, 그림 해석 범위, 500/100 token 정의를 유지한다. 아래의 구조 연결은 제안 당시의 표현이며 실제 적용 여부는 실시 기록에서 확인한다.

## 1. 확인한 원인

조건 연결 미결 9건은 PDF 순번 287쪽의 질문 3개·조건 박스 3개와 330·332·334쪽의 첫 조건 박스 각 1개다. 네 쪽 모두 native 문자층을 사용하므로 우선 해결할 문제는 OCR 재인식이 아니라 구조 연결이다.

현재 `prepare_box_contracts.py`는 KNOWN INFO 제목의 y좌표가 질문 박스 위쪽보다 45 point 이상 위에 있으면 연결 후보에서 제외한다. 330·332·334쪽의 첫 제목은 각각 약 49.8, 50.7, 47.2 point 위에 있어 이 범위를 벗어난다. 실제 PDF에서는 왼쪽 박스가 길어서 위에서 시작하며, 각각 10·13·16번 질문 옆에 놓여 있다. 이 세 건은 원문 판독 불능이 아니라 연결 규칙의 한계다.

287쪽은 다른 배열이다. B1에는 바로 대응하는 왼쪽 조건 박스가 없고, 아래의 세 박스를 B1·B2·B3에 순서대로 붙이면 마지막 박스의 좁혀진 가능 원인을 너무 이른 단계에 적용한다.

## 2. 네 쪽에 적용할 연결

쪽수는 PDF 순번이며 괄호는 인쇄 쪽번호다.

| 대상 | 제안하는 처리 | 보존할 내용과 확인 기준 |
| --- | --- | --- |
| 330 (2-234) | 첫 왼쪽 박스를 질문 10에 명시적으로 연결한다. 기존 11·12번 연결도 같은 페이지의 박스 경계와 대조한다. | KNOWN INFO의 BATTERIES OK·LEAD 57B GROUND OK와 POSSIBLE PROBLEMS의 고장 후보 목록을 구분한다. 질문의 RUN 및 ENGINE NOT RUNNING을 유지한다. |
| 332 (2-236) | 첫 왼쪽 박스를 질문 13에 연결한다. 14·15번에만 적힌 추가 정상 조건이 13번으로 유입되지 않도록 검사한다. | PCB와 distribution box의 LED 13 설명, 엔진 작동 온도 조건을 원문 그대로 유지한다. |
| 334 (2-238) | 첫 왼쪽 박스를 질문 16에 연결한다. 질문 17·18의 조건은 각자 보존한다. | 16번의 FOR DISTRIBUTION BOX, IF YES, GO TO 18. 및 17·18번의 distribution box 관련 NOTE를 누락하지 않는다. 18번에 있는 GLOWPLUG CONTROLLER OK를 앞 단계에 복사하지 않는다. |
| 287 (2-204), B1 | 기종 확인 질문으로 두고 왼쪽 박스를 순번으로 붙이지 않는다. 명시적인 SEE NOTE ON OPPOSITE PAGE를 288쪽의 기종별 NOTE에 연결한다. | 실제 연결할 별도 조건 박스가 없는 상태와, 있어야 할 조건을 놓친 상태를 구별한다. 기종별 설명은 원문 구간을 참조하며 새로 요약하지 않는다. |
| 287, B2·B3 | 위쪽 첫 조건 박스는 B2, 두 번째 박스는 B3의 맥락으로 연결하는 안을 채택한다. | 원문 배치와 다음 쪽의 이어지는 단계에 근거한 구조 판정이다. 두 박스의 원문은 모두 출력 전압 이상을 KNOWN INFO로, ALTERNATOR와 WIRING을 POSSIBLE PROBLEMS로 제시한다. |
| 287, 마지막 조건 박스 | B3의 시작 조건으로 붙이지 않는다. B3 아래의 계속 진행 구간에 있는 상태 정보로 보존하고 GO TO B4, Page 2-206의 원문 참조를 연결한다. B4의 직접 조건은 289쪽의 자체 박스를 사용한다. | 마지막 박스에는 POSSIBLE PROBLEMS로 ALTERNATOR만 남는다. 289쪽 B4에는 FIELD VOLTAGE OK가 명시되어 있다. 화살표의 뜻을 풀어 쓴 정비 문장은 추가하지 않는다. |

287쪽의 연결 근거는 PDF 125·126쪽의 흐름도 사용 안내, 287쪽 원문, 288쪽 참고 설명, 289쪽 B4의 시작 조건을 함께 대조한 것이다. 마지막 조건 박스의 위치와 분기 관계는 그림에 의존하는 구조 주석으로 남긴다. 검토를 마쳤다는 이유로 텍스트만으로 전체 진단 경로를 재현했다고 표시하지 않는다.

KNOWN INFO는 그 단계에서 알려진 상태이고, POSSIBLE PROBLEMS는 가능한 고장 원인이다. 후자에 BAD가 적혀 있어도 모두 이미 확인된 고장이라는 뜻으로 합치지 않는다. 원문 제목 두 개를 직렬화에서도 구별한다.

## 3. 공통 연결 규칙의 보완

- 전역 y좌표 허용 범위를 늘리는 방법은 쓰지 않는다. 질문·왼쪽 정보·오른쪽 시험 설명의 실제 테두리와 단계 식별자로 후보를 찾는다.
- 왼쪽 박스 전체의 세로 범위, 질문과의 겹침, 다음 단계 박스의 경계를 함께 검사한다. 후보가 여러 개이면 자동 확정하지 않는다.
- 위 네 쪽은 원문에서 확인한 `박스 ID → 단계 ID/계속 진행 구간` 관계를 별도 입력으로 고정한다. 생성 프로그램과 검사 프로그램은 이 입력을 각각 읽는다.
- 조건 본문은 상자 내부의 문자만 가져온다. 다음 KNOWN INFO 제목까지 모두 가져오는 현재 방식은 박스 밖 문자가 섞일 가능성이 있으므로, 실제 박스 범위를 확인한 계약으로 대체한다.
- REPLACE 등 분기 뒤의 조치 문자는 독립적인 무조건 정비 권고로 내보내지 않는다. 원래 질문·분기 표식·PDF 위치를 함께 기록하고, 원문에 없는 조건 문장을 생성하지 않는다.
- 맞은편 참고 페이지는 실제 페이지 참조와 대응 표시를 확인한 영역만 연결한다. 331·333·335쪽의 경고·참고 설명은 구현 단계에서 대조할 대상이며 이번 검토에서 확인 완료로 계산하지 않았다.

## 4. 다른 OCR 혼합 구간의 처리

현재 CROSS_REGION_TEXT는 2,795건/240쪽이며, 검토 항목의 출처 기준으로 OCR 2,748건과 native 47건이다. 이는 독립적인 문자 오류 2,795개라는 뜻이 아니다. 다른 구조 검토 항목과 같은 원문 영역을 중복으로 가리킬 수 있다.

217쪽에는 `PCB OK DISCONNECT WIRE 569C AT COLD ...`처럼 왼쪽 상태 정보와 가운데 질문, 오른쪽 시험 방법이 한 줄로 합쳐진 사례가 있다. 262쪽도 같은 유형이다. 한편 native 47건에는 가운데 질문의 긴 줄이 고정 x좌표 경계를 넘는 사례가 포함되어 있어, 실제 혼합인지 먼저 분류해야 한다.

| 구분 | 처리 방법 | 문자 보정 여부 |
| --- | --- | --- |
| 정상 문장이 고정 열 경계를 넘음 | 실제 박스 경계 안에 있는 줄임을 확인하고 해당 박스에 배정한다. | 문자 변경 없이 구조만 수정 |
| 문자는 맞으나 여러 영역이 한 줄로 합쳐짐 | 낱말 또는 문자 좌표로 원래 박스에 분배하고 박스 내부 읽기 순서를 복원한다. 기존 문자열의 각 구간과 대응시킨다. | 기존 문자 구간의 재배열이면 구조 변경으로 기록 |
| 기존 좌표가 줄 단위여서 분해가 불가능함 | 같은 고정 OCR 환경에서 단어 좌표를 보존하는 보조 출력을 만든다. 기존 추출과 문자 대응을 먼저 확인한다. | 좌표 보완만으로 해결하면 문자 변경 없음 |
| OCR이 단어까지 합치거나 오독함 | 해당 박스를 원본 PDF에서 잘라 박스 단위로 OCR한다. 엔진·언어 데이터·해상도·영역·PSM 등을 고정한다. | 새 OCR은 후보로 보존하고, 채택하는 문자 변경은 다음 보정 목록에 기록 |
| 박스별 OCR 뒤에도 오독이 남음 | Codex가 PDF와 대조하여 필요한 구간을 전사·교정한다. 전후 문자열·PDF 위치·이미지·사유를 남긴다. | 기존 보정 검증 프로그램으로 실제 차이와 목록의 일치를 검사 |
| native와 OCR이 같은 영역에 존재 | 각각의 전체 문자 대응과 원문을 확인해 채택한다. native가 쪽 참조만 담는 경우 OCR 본문을 통째로 버리지 않는다. | 추출층 선택과 문자 보정을 별도 기록 |

현재 `ocr_worker.py`는 Tesseract TSV의 단어 좌표를 읽지만 최종 산출물에는 합쳐진 줄 좌표를 중심으로 저장한다. 따라서 단어 좌표를 별도 산출물로 유지하는 개선이 우선이다. 같은 환경으로 다시 실행해도 문자열이 달라지는 경우에는 과거 텍스트와 좌표가 동일하다고 간주하지 않고 새 추출 후보로 취급한다.

표는 행·열·셀로, 진단 흐름도는 개별 박스로, 그림 주변 본문은 해당 본문 영역으로 나눈다. `580Ω`, `569C`, `93B`, `458B`, ON/OFF, NOT, PIN 대소문자 등은 일반 철자와 별도로 대조한다. OCR 신뢰도 값만으로 채택하거나, 원문에 없는 문장으로 매끄럽게 다시 쓰지 않는다.

## 5. 적용 순서와 종료 기준

1. 기존 v6/v3 결과·규칙·해시를 보존한다. 같은 PDF 영역을 가리키는 검토 ID를 묶어 작업하되 각 ID의 처리 범위가 모두 포함되는지 검사한다.
2. 네 쪽의 관계를 먼저 반영한다. 조건 연결 미결 9건마다 완료 판정과 그 근거를 남긴다. 문자 변경과 구조 변경을 별도로 집계한다.
3. 실제 혼합을 확인한 217·262쪽에 단어 좌표 분리와 박스별 OCR을 시범 적용한다. 두 결과를 원본 PDF와 전부 대조한 뒤 동일한 구조의 다른 페이지로 확대한다.
4. 확대할 때 레이아웃 유형별 규칙과 적용 페이지 목록을 고정한다. 기존 세부 규칙의 독립 표본 검사와, 오류 발견 시 같은 규칙 적용 구간 전체 재검사를 따른다. 숫자·부정·단위·식별자 차이 및 연결 예외는 각각 확인한다.
5. 새 문자 보정은 후속 batch와 새 corrected 버전으로, 관계·경계 변경은 새 corpus 규칙 버전으로 남긴다. 전체 833쪽 범위에서 corpus를 다시 생성한다. 정상 구간을 다시 OCR해야 한다는 뜻은 아니다.
6. 아래 조건을 검사하고 실시 기록을 갱신한다.

- 실제 문자 변경 = 보정 목록에 기록한 변경. 기록되지 않은 삭제·추가·치환 0.
- 채택 문자마다 본문·맥락·중복 대체 대상·그림 관련 기록 등 최종 위치가 있고, 설명되지 않는 누락 0.
- PDF에서 별도로 확인한 박스 관계와 출력의 연결 일치. 다른 단계의 조건이나 POSSIBLE PROBLEMS를 확정 사실로 옮긴 사례 0.
- 변경한 구간과 영향을 받는 같은 유형을 재검사. 네 쪽의 성공만으로 나머지 OCR 전체를 완료 처리하지 않음.
- 제목·조건을 포함해 청크당 최대 500 token, 같은 구조단위 본문 중첩 100 token 유지. 청크 수는 사전 고정하지 않음.
- 고정 입력·환경으로 두 번 생성한 corpus·출처·선택 기록의 해시 일치.
- 텍스트로 채택할 내용의 미해결 문자 선택·구조 판정 0. 명확히 확인한 그림 의존 관계와 원문 자체의 이상은 별도 분류하되, 미판독 문자를 이 분류로 옮겨 검토 완료 처리하지 않음.

기계 검사는 변경 이력과 정의한 관계의 일치를 확인한다. 처음에 그 관계를 올바르게 판독했는지는 PDF 대조로 확인하며, Codex의 대조와 연구자의 직접 검토 여부를 구별해 기록한다. 재생성 프로그램 자체에는 LLM 호출을 추가하지 않는다.
