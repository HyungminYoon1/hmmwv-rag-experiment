# 교범 검색 구조

검색은 기존 실험 설계의 BGE-M3 dense embedding, CPU float32, 문서 배치 8, L2 정규화, FAISS IndexFlatIP, Top-5를 따른다. 재순위화·질의 재작성·하이브리드 검색은 사용하지 않는다.

## 책임 분리

- `common.py`: 경로, 해시, JSON, 환경·코드 버전 기록.
- `source.py`: 고정 corpus를 읽고 청크·PDF 출처를 제공한다. 원본과 전처리 산출물을 수정하지 않는다.
- `download_model.py`: 공개 모델의 지정 revision을 다운로드하고 파일 해시를 남긴다. 다운로드는 초기 준비 단계에만 필요하다.
- `model.py`: 네트워크 없이 CPU float32 임베딩을 계산한다. 입력 잘림·비유한값·영벡터를 허용하지 않는다.
- `cpu_affinity.py`: 이 검색 프로세스의 CPU 배치를 확인하고 적용한다. Windows 전역 설정이나 다른 프로세스는 변경하지 않는다.
- `build.py`: 전체 청크를 벡터화하고 행 대응표와 인덱스를 생성한다. 중간 배치와 해시를 남겨 같은 입력·코드·환경에서 재개할 수 있다.
- `index.py`: 인덱스 무결성·corpus 대응을 확인하고 정확 검색을 수행한다.
- `benchmark.py`: 사용자 확정 의사가 있는 60개 평가질의를 보존한다. 개발용 검색에서 정규화한 동일 문항을 실행하지 않는다.
- `service.py`: 질문 검사, 임베딩, 검색, 결과 기록을 조정한다.
- `app.py`: localhost HTTP 요청을 검증하고 서비스에 전달한다. 모델 계산이나 검색 정책을 구현하지 않는다.
- `web/`: 검색·기록·자료의 세 화면. 결과 본문을 HTML로 해석하지 않는다.
- `verify.py`: 모든 벡터와 FAISS 행의 동일성, 재구성 인덱스, NumPy 점수, 전체 또는 표본 임베딩 재실행을 검증한다.

## 데이터와 실행

입력은 `preprocessing/output/corpus-v6-final`이다. 고정된 전처리 프로그램과 환경을 유지하기 위해 검색은 `retrieval/.venv`와 별도 모듈을 사용한다. 검색 앱은 `127.0.0.1:8766`, 기존 corpus 앱은 `127.0.0.1:8765`다. 기존 서버의 종료나 재시작은 필요하지 않다.

모델은 `models/`, 새 인덱스는 `indexes/`, 평가질의 사본은 `benchmarks/holdout-v1/`, 개발 검색 기록은 `runs/development/`, 확인 자료는 `reports/`에 둔다. 완료된 인덱스는 덮어쓰지 않는다. 모델과 corpus의 판본·설정·파이프라인 코드·패키지가 바뀌면 새 인덱스를 만든다.

검색 프로세스는 이 PC의 서로 다른 성능 코어 8개(논리 CPU 0·2·4·6·8·10·12·14)를 사용한다. 문서 배치는 토큰 길이 내림차순·청크 ID 순서로 구성한 뒤 최종 벡터 행을 청크 ID 순서로 복원한다. 배치 순서를 기록하고 전체 문서 벡터를 독립 프로세스에서 다시 계산해 동일성을 확인한다. 이 검증을 통과하지 않은 인덱스는 앱에서 사용하지 않는다.

FAISS에는 정규화한 벡터만 저장하고, 결과는 원본 청크 ID로 본문·PDF 위치와 결합한다. 모든 점수를 받아 점수 내림차순·ID 오름차순으로 정렬한 후 5개를 반환하므로 경계 동점도 일관되게 처리한다. 이는 새 재순위화 모델이 아니라 설계에 명시한 동점 규칙이다.

검색 요청과 결과는 PC 안에 저장하며 자동 삭제하지 않는다. 외부 서버에 질문·교범을 전송하지 않는다. 개발용 요청에는 원문 질문, 순위·유사도·본문·출처, 코드·설정·모델 버전, 시간 구간을 기록한다. 이 시간은 기능 점검 기록이며 정식 응답시간 결과로 집계하지 않는다.

현재 모듈은 검색까지 담당한다. LLM 답변 생성, 정답 근거·청크 매핑 확정, RAGAS 평가, 정식 60문항 실험은 다음 단계다.
