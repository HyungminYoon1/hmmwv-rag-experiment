# HMMWV 교범 검색 기능 구현 기록

2026-09-28. 고정된 전처리 결과를 검색하는 로컬 프로그램을 구현하고 실제 실행 검증을 완료했다. 전체 8,344개 문서 벡터의 독립 재계산 결과가 바이트 단위로 일치했고, 검색 화면·원문 표시·기록 저장을 확인했다. 최종 60문항의 성능 평가는 아직 실행하지 않았다.

## 1. 구현 범위

`retrieval/`에 검색 코드·실행 환경·모델·인덱스·실행 기록을 분리했다. 기존 `preprocessing/`의 고정 코드, corpus, 보정 기록, 8765 앱을 수정하지 않는다. 검색 앱은 `http://127.0.0.1:8766/`에서 제공하며 프로젝트 최상위의 `교범 검색 실행.cmd`로 실행한다.

- **교범 검색:** 질문을 입력하면 관련 청크 5개와 유사도를 표시한다. 원문 보기를 누르면 해당 청크의 출처 영역을 표시한 PDF 이미지를 연다.
- **검색 기록:** 질문별 검색 순위·점수·본문·PDF 쪽·설정·코드 버전·시간을 로컬 JSON으로 보관하고 다시 열거나 내려받는다.
- **검색 자료:** corpus와 모델·인덱스 설정, 평가질의 보존 상태, 재현 정보를 확인한다.

검색은 BGE-M3의 dense embedding을 사용한다. LLM 답변 생성, 정답 근거 확정, RAGAS, 최종 평가 실험은 이번 작업에 포함하지 않았다. 검색 점수는 문서와 질문의 벡터 유사도이며 정답 확률이 아니다.

## 2. 사용 데이터와 검색 설정

| 항목 | 적용 내용 |
| --- | --- |
| 교범 | TM 9-2320-280-20-1, 1996 / Change 2 (2004) |
| corpus | `preprocessing/output/corpus-v6-final` |
| 연구 범위 | 제1·2장, PDF 31–863쪽, 833쪽 |
| 문서 수 | 고정 청크 8,344개 전체 |
| 임베딩 | BAAI/bge-m3, 1,024차원, CLS pooling |
| 모델 revision | `5617a9f61b028005a4858fdac845db406aefb181` |
| 계산 | CPU float32, 문서 배치 8, CPU thread 8, interop thread 1 |
| CPU 배치 | 이 프로세스에 논리 CPU 0·2·4·6·8·10·12·14 지정 |
| 문서 배치 순서 | BGE 토큰 길이 내림차순, 동점 청크 ID 순. 최종 벡터 행은 원래 ID 순서로 복원 |
| 정규화·검색 | 문서·질의 L2 정규화, FAISS CPU IndexFlatIP 정확 검색 |
| 결과 | Top-5, 점수 동점은 청크 ID 오름차순 |
| 추가 검색 기법 | 재순위화, 하이브리드 검색, 질의 재작성 미사용 |
| 문서 입력 길이 | BGE 기준 최대 531토큰 / 한도 8,192토큰, 잘림 0건 |

청킹에 쓰인 Qwen tokenizer와 임베딩에 쓰인 BGE tokenizer는 다르다. 최대 500 Qwen 토큰으로 나눈 청크가 BGE 기준 531토큰인 것은 입력 손실을 뜻하지 않는다. 고정 청크의 본문 전체를 임베딩했다.

모델은 BAAI 공식 저장소의 지정 revision에서 확보했다. 2,271,145,830 bytes인 가중치 파일의 SHA-256이 공식 LFS 해시와 일치했다. 검색은 확보된 로컬 파일만 읽으며 외부 생성형 AI API를 호출하지 않는다. 모델 파일 해시, 패키지 버전, 코드·설정, 벡터 행·청크 대응표를 기록했다.

## 3. 60개 평가질의 보존

사용자의 결정에 따라 기존 60개 문항을 최종 결과용으로 잠정 고정했다. 단일 근거 20개, 다중 근거 30개, 답변불가 10개다. HWPX·CSV·채점기준 JSON·근거 문서를 `benchmarks/holdout-v1/`에 바이트 그대로 복사하고 원본 해시를 남겼다.

CSV와 JSON의 ID·유형·질문이 일치하고, 문항 수와 중복 여부도 확인했다. 문항 문구를 바꾸지 않았다. 정답 근거와 최종 청크 대응표 검증은 `PENDING_SOURCE_AND_CHUNK_VALIDATION`으로 남겼다. 이는 질문을 다시 선정하겠다는 뜻이 아니라, 같은 질문을 어떻게 채점할지 원문에 맞춰 확인하는 후속 작업이다.

개발 검색에는 별도 질문을 사용한다. 보존 문항과 대소문자·구두점·공백을 정규화한 질문이 같으면 임베딩 전에 거부한다. 의미가 같은 바꿔쓰기까지 식별하는 기능은 아니다. 연구 감독자의 지침 또는 심각한 문항 결함이 확인되면 사유와 변경 이력을 남겨 새 버전을 만든다.

## 4. 구현 중 발견한 계산 문제

초기 CPU 실행에서 유효하지 않은 문서 벡터가 발생했다. 이어서 같은 입력을 반복 계산했는데 값이 달라지는 현상도 확인했다. 실패한 부분 인덱스, 패키지 조합별 진단, 공식 ONNX 모델을 이용한 비교 자료를 보존했고 최종 검색에서는 사용하지 않는다.

검색 프로세스를 이 PC의 서로 다른 성능 코어 8개로 제한한 뒤 표본의 반복 결과가 바이트 단위로 일치했다. 이 구성을 명시적으로 적용하고 전체 문서 벡터도 별도 프로세스에서 다시 계산하도록 했다. CPU·라이브러리 내부의 정확한 원인은 특정하지 않았다. BIOS, Windows 전역 설정, 다른 앱의 CPU 배치는 변경하지 않았다.

최종 패키지는 PyTorch 2.8.0+cpu, Sentence Transformers 5.1.1, Transformers 4.55.4, FAISS CPU 1.15.1이다. 설치 환경 전체는 `requirements.lock.txt`에 기록한다. 다른 PC 또는 다른 패키지 환경에서 같은 결과가 자동 보장되는 것은 아니므로 해당 환경에서 새 인덱스와 검증 기록을 만들어야 한다.

세부 선택지·판단 근거·관련 파일은 [결정 기록](../DECISIONS.md)의 R06–R08에 남겼다.

| 최종 평가 | 60문항을 이용한 검색 성능 측정·LLM 답변 생성·RAGAS 모두 NOT_RUN |

근거: [인덱스 전체 검증](index-verification.json), [13개 기능 검사](unit-tests.json), [실제 HTTP 검색](http-smoke.json), [브라우저 확인](browser-qa.json), [다운로드 대조](browser-export.json), [기존 입력 보존](frozen-inputs-preserved.json).

평가질의 차단을 확인하는 요청은 임베딩 전에 거부됐고 검색 기록을 생성하지 않았다. 개발 질문의 검색 순위가 좋은지 평가하거나 그 결과에 맞춰 검색 설정을 조정하지 않았다. 위 결과는 구현·자료 보존·계산 재현성의 검증이며, 60문항의 검색 정확도 결과가 아니다.

인덱스 생성에는 이 실행에서 675.82초가 걸렸다. 원본 검증·모델 로딩·벡터화·파일 쓰기를 포함한 구현 기록이며, 통제된 성능 측정값으로 사용하지 않는다. 인덱스와 벡터 행렬은 각각 약 34.2 MB이고 모델 배포 파일은 약 2.29 GB이다.

앱은 corpus·모델·인덱스·파이프라인 해시와 환경 버전을 대조하며 해당 인덱스의 전체 재계산 PASS 기록이 있어야 시작한다. 같은 파일 이름으로 완료 인덱스를 덮어쓰지 않는다.


## 6. 자료 확인 범위

| 자료 | 상태와 확인 범위 |
| --- | --- |
| 실험 정의·처리 규칙 v1.0 | VERIFIED — 문서 내용을 읽고 검색 설계와 평가질의 분리 원칙 확인 |
| corpus-v6-final | VERIFIED — 8,344개 청크를 읽고 본문 해시·ID·입력·출력·고정 코드 해시 대조. 원문 모든 쪽의 의미를 새로 판정한 검사는 아님 |
| 평가질의 CSV·채점기준 JSON | PARTIAL — ID·유형·문항의 일치와 중복·개수 및 원본 해시 확인. 문항별 정답 근거·심각한 결함 검토는 후속 단계 |
| 평가질의 HWPX·근거 문서 | PARTIAL — 원본과 사본의 바이트 동일성 확인. HWPX 지면을 다시 검토하지 않음 |
| 공개 모델·FAISS·Sentence Transformers 문서 | VERIFIED — 이번 구현에 사용한 모델 로딩·정규화·검색 API와 공개 배포 정보를 확인 |

공개 구현 근거의 링크는 [결정 기록의 공개 구현 근거](../DECISIONS.md#공개-구현-근거)에 모았다. 이 자료는 프로그램 구성의 근거이며 교범 검색 정확도를 입증하는 결과는 아니다.

## 7. 후속 실험 작업

같은 60개 질문에 대해 원문 근거와 `corpus-v6-final`의 청크 ID를 대응시킨다. 답변불가 문항도 현재 텍스트 연구 범위와 일치하는지 확인한다. 근거 대응표는 검색 결과를 보고 정답을 바꾸는 방식으로 작성하지 않는다.

그다음 동일한 로컬 LLM을 쓰는 LLM Only / RAG 실행기를 연결하고 프롬프트·문맥 조립·응답 기록·워밍업·반복 실행을 구현한다. 실행 조건과 채점 기준을 고정한 후 최종 60문항을 실행한다. 이번 구현의 개발 검색 결과는 그 성능 결과와 별도로 보관한다.

실행·재현 명령은 [README](../README.md), 모듈별 책임은 [architecture.md](../architecture.md)에 있다.
