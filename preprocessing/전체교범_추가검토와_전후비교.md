## 원문 문제로 남긴 부분

- **PDF 118쪽:** `Metal particles are`는 원문 자체에서도 불완전하다. 다음 119쪽은 부품 목록이며, 누락 내용을 추정해 넣지 않았다. 함께 문제로 보았던 `Change fluid every 12,000 miles`는 성립하는 명령문이므로 후속 검토에서 판정을 정정했다.
- **PDF 98쪽:** `Belt`가 원문에서도 점검 주기 열에 놓여 있다. 단어 내부 공백만 제거하고 임의로 옆 열로 옮기지 않았다.
- **PDF 61·296쪽:** 원문에 단위 대응이 의심되는 수치가 있다. 환산값을 새로 계산해 원문 수치를 교체하지 않았다.
- **PDF 97쪽:** 타원 안의 D 기호를 OCR의 `(QD)`로 그대로 채택하면 부정확하다. 도형 기호의 표현을 확정하지 않은 항목으로 남겼다.
- `Teat`, `currant`, `Procedureas` 등은 일부 위치에서 PDF 화면 자체에도 나타난다. 이들은 추출 오류로 고치지 않았다.

상세 목록: `review-v2/verified-v3-a/source-issues.jsonl`.

native/OCR 줄 차이 801건 중 54건은 원문 대조 보정과 연결되었고 190건은 공백·문장부호 등의 표기 차이로 자동 분류했다. 나머지 **557건은 자동 대체하지 않은 레이어 간 차이 후보**로 남겼다. 모두 실제 오류 557건이라는 뜻은 아니다. OCR이 그림 글자나 다른 단의 문장을 합친 경우도 포함된다. 기존 OCR 저신뢰 경고 전체에 대한 글자별 대조도 끝난 것은 아니다.

이 때문에 `corpus_ready_for_index`는 `false`다. 최종 corpus에서는 채택할 본문·표 레이어를 정하고, 남은 후보 중 실제로 채택되는 구간을 검수해야 한다. 추출 실패나 미검수 상태를 답변불가 질의의 근거로 사용하지 않는다. 순수 도해에 의존하는 내용은 별도로 표시한다.

## 재실행

프로젝트의 `preprocessing` 폴더에서 실행한다. 출력 폴더는 기존에 없는 이름을 사용한다. `batch-001`과 `batch-002`의 수정은 `batch-003`에 누적되어 있으므로 세 번 순차 적용하지 않는다.

```powershell
.\.venv\Scripts\python.exe -X utf8 .\correct_extraction.py --ledger .\corrections\batch-003\correction-log.json --output .\output\corrected-v3-c
.\.venv\Scripts\python.exe -X utf8 .\verify_corrections.py .\output\corrected-v3-c --ledger .\corrections\batch-003\correction-log.json --report .\audit\corrections-v3-c.json
.\.venv\Scripts\python.exe -X utf8 .\build_reviewed_structures.py --revision 3 --output .\review-v2\verified-v3-c
.\.venv\Scripts\python.exe -X utf8 .\verify_whole_manual_review.py
```

마지막 명령은 납품된 a/b 결과와 원본 보존·구조를 다시 검사한다. 새 c 폴더를 그 명령이 비교하는 것은 아니다. 구조 생성 프로그램은 고정된 `corrected-v3-a`를 입력으로 사용한다.

보정 재실행은 원본 PDF·고정 추출본·수정 기록을 입력으로 사용하는 로컬 프로그램이다. 재실행 중 LLM은 호출하지 않는다. 새로운 Codex 세션에서 같은 보정 판단을 다시 생성해도 결과가 같다는 주장은 하지 않는다.
