# 전체 교범 파싱 결정 기록

작성일: 2026-09-22

## F01. 전체 파싱과 검색 범위 구분

- 맥락: 사용자는 공정성을 위해 교범 전체를 처리해야 하는지 확인하고 파싱을 요청했다. 기존 실험 규칙은 제1·2장 본문과 문자로 복원 가능한 표를 검색 범위로 정했다.
- 선택지: 정답 근거가 있는 부분만 처리 / PDF 전체를 검색에 투입 / PDF 전체를 파싱하되 기존 검색 범위를 유지.
- 결정: PDF 1~890쪽을 모두 파싱하고, 31~863쪽 833쪽은 검색 범위, 표지·안내·목차·색인 등 나머지 57쪽은 범위 밖으로 표시한다. 본문의 정답 관련 여부로 범위를 줄이지 않는다. 이번 프로그램은 평가질의 파일을 읽지 않는다.
- 이유: 검색에 정답과 무관한 본문도 포함하면서 기존 연구 범위와 답변불가 정의를 유지한다. 전체 파싱은 누락·쪽수·출처 확인에 이용한다.
- 관련 파일: `parse_full_manual.py`, `page_coverage.jsonl`, 전체·실험범위 텍스트 파일.
- 후속 확인: 검색 범위를 나중에 변경한다면 최종 질의의 답변가능 여부와 근거 대응표도 다시 확인한다.

## F02. 원래 텍스트가 많아도 이미지 안의 문자를 검사

- 맥락: 기존 OCR 기준은 원래 본문이 350자 미만인 이미지 포함 페이지였다. PDF 300쪽처럼 본문이 350자를 넘지만 그림 안의 표가 빠지는 사례를 확인했다.
- 선택지: 기존 기준 유지 / 교범 전체를 OCR로 대체 / 모든 이미지 포함 페이지에 OCR을 병행하고 원래 텍스트와 별도로 보관.
- 결정: 모든 래스터 이미지 포함 페이지와 350자 미만의 벡터 선·도형 포함 페이지, 기존 OCR 페이지를 검사한다. 원래 텍스트는 전체에서 다시 읽는다.
- 이유: 글자 수가 충분하다는 이유로 그림 속 글자까지 추출됐다고 가정하지 않는다. OCR이 손글씨나 선을 잘못 읽는 경우도 있으므로 원래 텍스트를 OCR로 일괄 교체하지 않는다.
- 관련 파일: `parse_full_manual.py`의 `PROFILE`, `ocr-snapshot/`, `raw_native_pages.jsonl`, `pages.jsonl`.
- 후속 확인: OCR은 도면 의미를 복원한 결과가 아니다. 문단·표·그림 영역을 분리하고 필요한 문자 근거만 검수 후 채택한다.

## F03. 원래 내용의 자동 재작성 금지

- 맥락: OCR 단위 오인식과 표 열 혼합이 확인됐다. 원래 텍스트층에도 영문 I와 소문자 l의 혼동이 있다. 원문 자체의 철자나 쪽번호 오류도 있을 수 있다.
- 선택지: LLM으로 전체 교정 / OCR 결과를 자동 채택 / 출처에 따른 오류 판정 후 위치별 보정.
- 결정: 이번 추출에서는 내용을 자동으로 고치지 않는다. 낮은 OCR 신뢰도, 이상 문자, 단위 혼동 후보를 좌표와 함께 기록하고, 별도 원문 대조에서 확인한 보정 필요 사례를 문서화한다.
- 이유: 문장 유창성과 교범의 사실·조건 보존은 다르다. 원문에 없는 절차·단위·분기 관계를 추가하지 않고, 원문 오류와 추출 오류를 구별해야 한다.
- 관련 파일: `review_signals.jsonl`, `normalization_log.jsonl`, `전체교범_파싱_검토결과.md`.
- 후속 확인: 보정이 필요하면 수정 전후·페이지·좌표·원문 근거를 버전이 있는 보정 목록으로 저장한다. LLM을 사용하더라도 후보 제안으로만 취급하고 원문으로 확정한다. 이번 실행에서는 LLM을 호출하지 않았다.

## F04. 고정 OCR 입력을 이용한 재현

- 맥락: 이전 조사에서 새 OCR 계산의 완전한 바이트 일치는 확인하지 못했다.
- 선택지: 매번 새 OCR 수행 / 이전 전체 산출물 복사 / 원본을 재파싱하고 고정 OCR 추출본을 입력으로 사용.
- 결정: 이전 501쪽 OCR은 해시를 확인해 보존하고 추가 대상만 새로 OCR한다. 확장된 추출본을 별도 버전으로 고정하여 원본 재파싱·이미지 해시 검사·텍스트 정리·표 열 추출·검토자료 생성을 다시 실행한다.
- 이유: OCR의 반복 실행 일치와, 고정 입력으로 전처리 결과를 재현하는 검증을 구분한다. 원본은 바꾸지 않고 이전 산출물도 보존한다.
- 관련 파일: `assets/ocr-full-manual-v2`, `parse_full_manual.py`, `verify_full_manual.py`, `audit/full-manual-verification.json`.
- 후속 확인: 이번 재현성 검사로 문자 정확도나 최종 RAG 성능을 입증했다고 표현하지 않는다.

## F05. PDF 문자 매핑 오류도 OCR 대상으로 포함

- 맥락: 전체 품질 검사에서 PDF 868~871쪽의 원래 텍스트가 제어문자로 추출되는 문제를 발견했다. 원문 렌더링은 읽을 수 있는 서식인데 이미지 개수는 0이었다. 단순한 이미지 유무나 문자 수 기준으로는 이를 발견하지 못한다.
- 선택지: 깨진 문자를 LLM으로 추측 복원 / 범위 밖이라는 이유로 방치 / 원문 렌더링을 OCR.
- 결정: 원래 텍스트층에 대체 문자나 비정상 제어문자가 있으면 OCR 대상으로 추가한다. 원래 추출 내용도 보존한다. v1의 698쪽에 4쪽을 추가한 `ocr-full-manual-v2` 702쪽을 최종 고정 추출본으로 사용한다.
- 이유: 원문을 읽어 복원할 수 있는 문제여서 생성형 추론이 필요하지 않다. 검색 범위 밖 자료도 전체 파싱의 품질 검사 대상에 포함한다.
- 관련 파일: `parse_full_manual.py`의 `invalid_native_mapping`, `assets/ocr-full-manual-v2`, `verify_full_manual.py`.
- 후속 확인: 서식의 손글씨·열 구조와 OCR 오인식은 여전히 검수 대상이다. 읽을 수 있는 문자로 바뀌었다는 사실을 완전한 정확성으로 표현하지 않는다.
