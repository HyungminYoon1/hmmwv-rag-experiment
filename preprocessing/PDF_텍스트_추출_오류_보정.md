# PDF 텍스트 추출 오류 보정

작성일: 2026-09-22. 이번 버전은 `batch-001`이다.

**후속 결과:** [557건 추가 검토와 보정 결과](557건_추가검토와_보정결과.md). 최신 결과는 `output/corrected-v4-a`와 누적 379건의 `batch-004`다. [v3 검토 기록](전체교범_추가검토와_전후비교.md)도 보존한다. 아래 내용은 최초 51건을 처리한 이력이다.

## 적용 결과

규칙 기반 추출본을 보존하고 Codex가 원본 PDF 이미지에서 확인한 **51건**을 별도 보정본에 반영했다. 27개 PDF 페이지의 29개 텍스트 레코드가 바뀌었다. 원본 PDF와 `output/full-manual-v2-a`의 기존 추출 자료는 변경하지 않았다.

- `STE/lCE` → `STE/ICE`: 46건. 전체 추출 자료에서 해당 패턴을 찾아 각 위치의 PDF 이미지를 확인했다.
- `Ib-ft`·`Ib-in` → `lb-ft`·`lb-in`: 2건. 수치는 유지했다.
- PDF 103쪽의 이전에 확인한 표 셀 추출 오류: 3건. `g. Any class III leak`, `(Cont'd)`, 괄호·master의 첫 글자와 테두리 잡음을 보정했다.

전체 자료에서 두 문자 혼동 패턴을 검색했으며 평가질의는 읽지 않았다. 표 셀 3건은 앞선 원문 대조에서 발견한 문제를 처리했다. 이번 작업을 전체 교범의 오타를 모두 교정한 결과로 보지 않는다. 다른 추출 오류, 표 구조와 도면 의존성에 대한 검토는 남아 있다.

원문 이미지 대조는 **Codex가 수행**했다. 사용자가 직접 원문을 검증한 결과로 기록하지 않았다. 프로그램의 일치 검사는 변경 이력을 검증하며 수정 내용의 의미적 정확성까지 판정하지 않는다.

비교용 텍스트의 식별자·구분 표시는 이번 프로그램에서 붙였다. 본문 내용은 기존 `pages.jsonl`의 `native_body_text`, `ocr_body_text`, 표 셀 문자열을 그대로 가져온다. 이 대응도 검증 프로그램이 확인한다. 기존 파일의 줄바꿈이나 머리말을 다른 형식으로 바꾼 것을 본문 보정 건수로 세지 않는다.

원래 텍스트와 OCR은 대안 추출 결과이며 같은 내용을 포함할 수 있다. 이 비교용 텍스트 전체를 그대로 임베딩하지 않는다. 보정 후 채택할 본문과 표를 확정하고 구조 검수를 거쳐 청킹한다. 기존 원시 블록·좌표 자료는 그대로 보존하며, 새 보정 레코드와 수정 위치를 연결해 추적한다.

## 프로그램의 검사 방식

1. 원본 PDF와 규칙 기반 `pages.jsonl`의 SHA-256이 수정 기록에 고정한 입력과 같은지 확인한다.
2. 보정 전 1,867개 레코드가 기존 추출 자료의 문자열·출처와 같은지 확인한다.
3. 수정 기록의 ID·대상·문자 위치·수정 전 문자열·중복·겹침을 검사한다. 위치는 보정 전 문자열의 0부터 시작하는 Unicode 문자 순번이며 끝 위치는 포함하지 않는다.
4. 보정 적용 함수와 별도로, 실제 보정본의 변경 전후 구간을 검사한다. 기록된 교체가 모두 반영되었는지, 그 사이와 마지막의 미수정 구간이 그대로인지 확인한다. 레코드 추가·삭제·순서와 메타데이터 변경도 확인한다.
5. 실제 보정본에서 문자 차이를 별도로 계산해 보고한다. 텍스트 출력 파일이 검증한 레코드와 같은지 확인하여 JSON은 정상인데 읽기용 텍스트만 다른 경우도 탐지한다.
6. 각 PDF 발췌 이미지를 원본에서 다시 렌더링하여 해시를 대조한다. 수정 기록 사본과 고정 원본, 산출물 목록과 파일 해시도 검사한다.

51건의 수정 기록이 실제 문자 비교에서 64개 차이 구간으로 나뉘었다. 하나의 셀 보정이 여러 문자 차이를 포함하기 때문이다. 두 숫자를 오류 개수나 오류율로 해석하지 않는다.

**실행 결과:** 1,867개 레코드 전체에서 기록되지 않은 변경과 미반영 수정이 없었다. 자동 검사 PASS, 오류 주입 시험 13/13 통과, 재실행 산출물 60/60개 해시 일치. 해시를 새로 계산한 뒤에도 기록 없는 내용 추가가 탐지되는지 시험했다. 입력·기록·코드를 모두 고정한 상태의 재현이며, Codex를 다시 호출하면 같은 보정 후보가 생성된다는 보증은 아니다.

## 다시 실행

현재 PC의 PowerShell에서 프로젝트의 `preprocessing` 폴더로 이동한 뒤 실행한다. `corrected-v1-c`는 새 출력 폴더여야 한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 .\correct_extraction.py --ledger .\corrections\batch-001\correction-log.json --output .\output\corrected-v1-c
.\.venv\Scripts\python.exe -X utf8 .\verify_corrections.py .\output\corrected-v1-c --ledger .\corrections\batch-001\correction-log.json --report .\audit\corrections-v1-c.json
```

검사 결과가 `PASS`인지와 종료 코드가 0인지 확인한다. 위 프로그램은 LLM이나 네트워크를 호출하지 않는다. Codex가 만든 보정 기록을 일반 프로그램으로 적용하고 검사한다. 원문 검토와 보정 후보 작성에는 Codex를 사용했으므로 전처리 전 과정에서 AI를 사용하지 않았다고 표현하지 않는다.

검증 프로그램 자체의 탐지 기능을 다시 시험하려면 다음을 실행한다. 임시 사본에만 오류를 주입하며 보관 중인 원본과 결과물은 수정하지 않는다.

```powershell
.\.venv\Scripts\python.exe -X utf8 .\test_correction_audit.py
```

새 보정은 기존 수정 기록을 덮어쓰지 않고 새 버전으로 만든다. 이 버전의 기준 수정 기록 SHA-256은 `458d6ab83e72db3898e05e4200610b20d43a69573e4f2a906469ee4ba2067e09`이다.

## 보정 기록과 후속 검토

PDF 텍스트 추출 오류 보정은 수정 목록과 자동 비교·재현 절차로 기록한다. 외부 AI의 전처리 보조 사용과 로컬 질의응답 실행을 구분하고, 보정 전후 기록과 도구 정보를 함께 보관한다. 모델·평가질의 수·평가 지표는 유지했다. 이 단계에서는 모델 비교실험을 수행하지 않았다.

보정 도구는 Codex(OpenAI), 사용일은 2026-09-22로 기록했다. 이번 세션의 정확한 백엔드 모델 ID를 독립적으로 확보하지 못했으므로 수정 기록에는 `null`과 사유를 남겼다. 향후 실제 모델 정보를 확인하면 별도 실행 기록에 보완하고 기존 기록을 소급해 다른 모델명으로 바꾸지 않는다.

기계 비교가 통과한 범위와 사람이 원문을 검증한 범위는 구분한다. 최종 평가질의의 필수 근거 대조 계획은 유지하며, 이번 자동 비교로 그 절차까지 완료했다고 보지 않는다.

## 결정 기록

- 맥락: 사용자는 보정본과 규칙 기반 추출본의 직접 대조 대신 실제 차이와 Codex 수정 기록의 일치 여부를 프로그램으로 검증하도록 요청했다.
- 선택지: 전체 텍스트를 다시 작성하고 사후 검수 / 위치별 수정 기록을 적용하고 전체 변경을 검증.
- 결정: 규칙 기반 추출본과 원본 PDF를 보존하고 위치별 보정 기록을 별도 버전으로 관리한다. 적용 프로그램과 실제 변경 검사 함수를 분리한다.
- 이유: 원문을 재작성하지 않고 변경 누락·추가를 기계적으로 찾을 수 있으며 같은 입력과 수정 목록으로 결과를 재생성할 수 있다.
- 관련 파일: `correct_extraction.py`, `verify_corrections.py`, `test_correction_audit.py`, `corrections/batch-001`, 실험 규칙 문서.
- 후속 검토: 다른 오류 유형, 표의 행·열과 연속 페이지 관계, 최종 근거 검증. 전체 corpus를 확정한 단계는 아니다.
