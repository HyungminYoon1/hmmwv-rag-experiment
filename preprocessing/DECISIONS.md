# 전처리 구현 결정 기록

작성일: 2026-09-22

## D01. 텍스트층과 OCR을 함께 보관

- 맥락: 이 PDF에는 텍스트층과 이미지가 함께 있다. 문서번호·쪽번호가 추출된다는 이유만으로 본문도 추출된다고 볼 수 없다.
- 검토한 방법: 텍스트층만 사용 / OCR 결과로 전체 교체 / 원래 텍스트와 OCR을 별도 보관 / 생성형 모델로 재작성.
- 결정: PyMuPDF의 원래 텍스트·좌표를 보존하고 필요한 페이지의 Tesseract OCR 결과를 별도로 저장한다.
- 이유: 원본 출처를 추적하면서 누락을 드러낼 수 있고, 실행 시 LLM이나 생성형 API가 필요하지 않다. OCR 결과의 오류가 기존 텍스트를 덮어쓰지 않는다.
- 관련 파일: `preprocess.py`, `config.json`, `pages.jsonl`, `raw_native_pages.jsonl`, `raw_ocr_pages.jsonl`.
- 후속 확인: 원래 텍스트가 350자 이상이어도 이미지 안의 글자가 빠질 수 있으므로 이미지 포함 페이지의 내용 범위를 확인한다.

## D02. 정비 점검표에 문서별 좌표 규칙 적용

- 맥락: 일반 표 인식만으로는 병합된 셀과 항목을 안정적으로 나누지 못했다. PDF 100쪽에서 운행 불가 판정 문구가 표 머리글에 붙고, 117쪽의 여러 항목이 한 행에 묶였다.
- 검토한 방법: 기본 표 인식 결과 사용 / 문서별 좌표 규칙 / LLM으로 표 재작성.
- 결정: PMCS 표의 다섯 열과 항목 번호 위치를 사용한다. 이미지인 97·103·111쪽은 원문 대조로 등록한 영역을 OCR한다.
- 이유: 절차와 운행 불가 조건을 분리하고, 같은 입력에 동일한 규칙을 적용할 수 있다.
- 관련 파일: `preprocess.py`의 `pmcs_rows`, `config.json`의 `pmcs_scanned_pages`.
- 후속 확인: 셀 OCR의 글자 정확성, 항목 전후 경고의 소속, 다음 페이지로 이어지는 행은 검수 후 확정한다. 이 규칙을 다른 교범에 그대로 적용하지 않는다.

## D03. 문자 추출과 그림의 의미 해석을 분리

- 맥락: 회로도와 진단 흐름도의 글자를 OCR하더라도 화살표·회로 연결·YES/NO 경로는 텍스트 순서만으로 확정할 수 없다.
- 검토한 방법: 모든 글자를 본문으로 채택 / 그림 포함 페이지 전체 삭제 / 원시 결과를 보관하고 의미 해석이 필요한 구간 표시.
- 결정: 원시 결과를 보관하고 검토 대상으로 표시한다. 자동으로 정답 근거나 최종 corpus로 채택하지 않는다.
- 이유: 현재 연구는 문자 근거만으로 답할 수 있는 질의를 대상으로 한다. 추출 실패를 답변불가로 잘못 분류하는 것을 막아야 한다.
- 관련 파일: `pages.jsonl`, `review_queue.jsonl`, `검토용_원문대조.html`.
- 후속 확인: 그림 전체를 해석할 필요 없이 독립된 문자 설명만으로 답할 수 있는 부분은 원문 대조 후 채택할 수 있다.

## D04. 자동 정규화 최소화

- 맥락: 단위·부정문·수치·하이픈은 정비 문서의 의미에 영향을 줄 수 있다.
- 검토한 방법: 문장 재작성과 자동 교정 / 줄끝 하이픈 일괄 삭제 / 출처가 명확한 형식 정리만 적용.
- 결정: 인식된 페이지 머리말·쪽번호와 줄 앞뒤 공백만 정리한다. 내용 교정은 하지 않는다.
- 이유: 틀린 내용을 그럴듯하게 바꾸는 것보다 변경 이력을 남기고 원문을 대조하는 것이 이번 실험에 적합하다.
- 관련 파일: `clean_lines`, `normalization_log.jsonl`.
- 후속 확인: 오인식 보정이 필요하면 위치·수정 전후·원문 근거를 별도 등록한다. 변경 후에는 전체 결과를 재생성한다.

## D05. 재현성 확인 범위

이 항목은 초기 검증 계획이다. 실제 비교에서 차이가 확인되어 최종 재현 경로는 D08로 정했다.

- 맥락: 같은 OCR 도구도 버전·언어 데이터·환경이 달라지면 결과가 달라질 수 있다.
- 검토한 방법: 설정만 기록 / 캐시 재사용 후 비교 / OCR을 포함한 독립 실행 후 파일 해시 비교.
- 결정: Python 환경·코드·설정·입력·언어 파일 해시를 기록하고, OCR 캐시를 공유하지 않는 두 실행의 모든 산출물 해시를 비교한다.
- 이유: 이번 PC와 고정된 환경에서 실제 재현되는지 확인하기 위한 것이다. OCR 정확성과 재현성은 서로 다른 검증이다.
- 관련 파일: `requirements.lock.txt`, `prepare_assets.py`, `manifest.json`, `verify.py`.
- 후속 확인: 도구나 규칙 변경 시 새 결과 폴더로 생성하고 이전 결과와 비교한다. 다른 운영체제에서 바이트 단위로 같다는 주장은 하지 않는다.

## D06. 최종 청킹은 원문 구조 확인 후 수행

- 맥락: 의미 단위와 표 행의 연결을 확정하기 전에 500 token으로 자르면 잘못된 열 관계나 경고 분리가 그대로 고정될 수 있다.
- 검토한 방법: 즉시 청킹 / 중간 추출 결과를 검수한 뒤 청킹.
- 결정: 이번 프로그램은 출처·좌표·본문·표·OCR·검토 목록을 만든다. 기존의 500 token 및 같은 단위 내 100 token 중첩 규칙은 유지하되 아직 실행하지 않는다.
- 이유: 사용자가 요청한 PDF 파싱 가능성 확인과 재현 가능한 전처리 도구를 먼저 완성하고, 실험용 corpus 확정 여부를 명확히 구분하기 위해서다.
- 관련 파일: `README.md`, `summary.json`, 기존 `research/2026-09-22_실험_정의와_처리규칙_v1.0.md`.
- 후속 확인: 표·경고·연속 항목과 60개 질의의 모든 필수 근거를 대조한 후 의미 단위 및 청크 대응표를 작성한다.

## D07. OCR 재현성 실패 기록과 엔진 조건 고정

- 맥락: 초기 PyMuPDF 내장 OCR의 독립 실행에서 22쪽의 OCR 결과가 달랐다. 원래 텍스트층과 PMCS 열별 결과는 같았다. 이어서 OCR에 들어간 픽셀의 해시를 기록하니 입력 이미지가 같아도 일부 OCR 문자가 달라지는 사례가 있었다.
- 검토한 방법: 스레드 설정 시점 조정 / 이미지마다 별도 프로세스 / 독립 Tesseract 빌드 및 연산 방식 고정.
- 결정: 공식 tesserocr 문서가 안내하는 Windows 빌드 중 tesserocr 2.10.0 / Tesseract 5.5.2를 사용하고 wheel 해시를 고정했다. 학습과 병렬 인식을 끄고 CPU 내적 연산을 generic으로 고정한다. 이미지마다 새 OCR 프로세스를 실행한다.
- 이유: 재현성을 가정하지 않고 실제 입력 픽셀과 결과를 대조할 수 있도록 하기 위해서다. 엔진 내부의 구체적인 결함 원인까지 확인한 것은 아니다.
- 관련 파일: `ocr_worker.py`, `requirements.lock.txt`, `preprocess.py`, `audit/verification_initial.json`, `audit/ocr_stage_probe.json`.
- 후속 확인: 이 조건에서도 새 OCR 계산의 차이가 남았다. D08의 고정 추출본을 사용한 최종 비교 결과는 `audit/verification.json`과 `검증결과.md`에 기록한다. 문자 인식의 정확성은 반복 실행 일치와 별도로 원문을 대조한다.

## D08. 원시 OCR 추출본을 명시적인 재현 입력으로 고정

- 맥락: D07의 설정을 적용해도 새 OCR 계산에서 일부 문자와 신뢰도 수치가 달라졌다. LLM을 도입해야 한다는 근거는 아니며, 자동 OCR을 매번 재계산하는 과정의 재현성 한계다.
- 검토한 방법: 실패한 비교를 무시 / 차이가 난 문자를 임의 삭제 / 원시 OCR 결과를 버전이 있는 입력 파일로 보관.
- 결정: OCR 추출본을 별도 파일·해시로 고정한다. `replay.py`가 원본 PDF를 다시 읽고, 같은 이미지인지 확인한 뒤 이 추출본을 사용해 전처리를 다시 실행한다. 새 OCR을 계산하는 `preprocess.py`도 남긴다.
- 이유: 연구에 사용할 텍스트의 출처와 변경 내역을 남기고, 고정된 입력에서 전처리 결과를 재현할 수 있도록 하기 위해서다. OCR을 다시 계산한 결과가 동일하다고 주장하지 않는다.
- 관련 파일: `freeze_ocr.py`, `replay.py`, `assets/ocr-snapshot/`, `audit/verification.json`.
- 후속 확인: 고정 OCR 추출본은 아직 내용 검수 전이다. 정확성 검토와 보정은 별도 버전으로 기록하고, 최종 corpus와 평가 근거 대응표는 이후 확정한다.
