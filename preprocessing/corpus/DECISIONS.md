# Corpus 앱 구현 결정

기준: 승인된 `research/2026-09-24_corpus_생성과_청킹_구현계획.md`. 2026-09-24 구현 세션.

## C01. 기존 입력을 고정하고 모듈별로 처리

- 맥락: 문자 보정은 v4까지 완료되었고, 구조 자료와 좌표 자료가 별도로 존재한다.
- 검토한 선택: PDF를 다시 추출하기 / v4 자료를 그대로 하나의 문자열로 연결하기 / 고정 입력을 검증하고 구조·선택·직렬화를 분리하기.
- 결정과 이유: 세 번째 방식. 21개 입력 파일을 SHA-256으로 잠그고 기존 보정 판단을 재현한다. 기존 원본은 변경하지 않는다.
- 관련 파일: `inputs.lock.json`, `common.py`, `build.py`, `select_spans.py`, `structure.py`, `serialize.py`.
- 후속 검토: 입력·판정 변경 시 새 버전과 변경 근거를 만들고 잠금 목록을 함께 갱신한다.

## C02. 미결 구조를 숨기지 않고 후보 corpus로 생성

- 맥락: 557건 판정은 전체 833쪽의 최종 구조 확정과 동일하지 않다.
- 검토한 선택: 미확정 구간 제외 / 원문 관계를 추정하여 완료 처리 / 후보와 미결 사유 보존.
- 결정과 이유: 세 번째 방식. 명시적 절·검토된 표는 구조화하고, 미확정 영역은 후보로 보존한다. 구간별 원시/OCR 대응·항목 경계·표 구조를 검토 목록으로 남긴다. 기계 검사 통과와 `corpus_ready_for_index`를 구분한다.
- 관련 파일: `select_spans.py`, `structure.py`, `verify.py`, `build.py`.
- 후속 검토: 검토 목록의 원문 대조와 판정 반영 후에 실험용 입력본을 고정한다. 이 앱에는 미결 항목을 무시하여 색인하는 기능이 없다.

## C03. 재현 가능한 문자·token·출처 처리

- 맥락: 연구 규칙은 Qwen 기준 500/100이며 LLM 보정의 임의 변경을 검출할 수 있어야 한다.
- 검토한 선택: 공개 청커 기본값 사용 / LLM으로 문장 재작성 / 자체 token 창과 문자 매핑.
- 결정과 이유: 고정 Qwen tokenizer를 사용하는 자체 창 분할. 필수 제목·조건을 지우지 않고, 제한·중첩·진행을 함께 만족하지 못하면 오류로 남긴다. 검증기는 보정 전후 레코드와 로그, 청크와 출처를 다시 비교한다. 표 열 이름과 구분자만 명시적인 직렬화 문자로 추가한다.
- 관련 파일: `chunk.py`, `serialize.py`, `verify.py`, `tests/test_corpus.py`.
- 후속 검토: 임베딩 단계에서 BGE-M3 tokenizer의 입력 길이는 별도로 확인한다. 사람의 의미 검토 완료를 기계 검증으로 대체하지 않는다.

## C04. localhost 서버와 저장 범위

- 맥락: 원문 표시와 오래 걸리는 생성·검증 작업을 브라우저에서 사용할 필요가 있다.
- 검토한 선택: 외부 서비스 배포 / 클라우드 API / 로컬 Python 서버.
- 결정과 이유: `127.0.0.1`에만 바인딩하는 표준 라이브러리 서버. Host·Origin과 프로세스 내 요청 토큰을 검사하며 임의 파일 경로를 제공하지 않는다. 브라우저는 외부 스크립트·폰트·API를 요청하지 않는다. 실행 로그에 요청 토큰을 남기지 않는다.
- 관련 파일: `app.py`, `web/`, `../run_corpus.ps1`, 프로젝트 최상위 `corpus 앱 실행.cmd`.
- 보관: 생성은 매번 별도 결과 폴더, 재검증은 `reports/`. 기존 결과는 자동 삭제하지 않는다. PDF 렌더링은 메모리에서 수행한다. 자동 시작 작업이나 방화벽 설정을 추가하지 않는다.
- 후속 검토: 공유 서버·원격 접속으로 확장할 경우 현재 localhost 전제를 별도로 검토해야 한다.

## C05. 화면을 목적별 URL로 분리

- 맥락: 사용자가 초기 화면의 과도한 설명과 현황 표시를 줄이고 주제별로 페이지를 분리하도록 요청했다.
- 검토한 선택: 단일 대시보드 / 한 화면에서 대형 카드 유지 / 공통 메뉴와 목적별 URL.
- 결정과 이유: `/chunks`, `/pages`, `/reviews`, `/runs`로 구분한다. 청크 화면에는 탐색과 선택한 내용만 두고, 본문·원문 대조·출처 기록은 선택 항목 내부에서 전환한다. 설정과 검증 설명, 실행 버튼은 생성·검증 페이지에 둔다. 현재 코드와 과거 실행 코드가 다르면 표시한다.
- 관련 파일: `web/index.html`, `web/style.css`, `web/app.js`, `app.py`.
- 후속 검토: 현재 검토 목록은 조회용이다. 판정 편집을 추가하려면 기존 결과 보존, 변경 이력, 입력 버전 갱신을 함께 설계한다.


## C06. 승인된 세부 규칙과 원문 대응 증거

- 맥락: 2026-09-24 사용자가 세부 처리 규칙 제안의 실행을 승인했다. 기존 입력·후보 결과·코드는 검증된 ZIP과 해시로 백업했다.
- 검토한 선택: 기존 중복 기준 유지 / 유사도 문턱 조정 / 공백만 정리한 문자 대응 및 원문 판정 기록.
- 결정과 이유: 세 번째 방식. 추출층 선택과 표 표현을 별도 기록하고, 자동 중복 처리에는 문자 구간의 대응 증거를 요구한다. 기존 557건 원문 판정은 해당 구간에 한해 재사용한다.
- 관련 파일: common.py, equivalence.py, select_spans.py, 후속 구조 규칙과 검증기. 기존 v4 보정 레코드는 보존한다.
- 후속 검토: 보류 숫자를 낮추기 위해 의미 확인을 생략하지 않는다. 새 문자 오류와 원문 이상은 구별하고, 새 발견은 보고서에 기록한다. 500/100 및 평가질의 미사용 원칙을 유지한다.

## C07. 원문 표의 별도 정의와 독립 검사

## C08. 추출층 선택과 표현 상태 분리

- 관련 파일: `common.py`, `equivalence.py`, `select_spans.py`, `verify_selection.py`, `tests/test_rules_v2.py`.
- 후속 검토: 원문 판정 229건의 대조 이미지를 SHA-256으로 고정했다. 대안 채택을 새 문자 보정이라고 부르지 않으며 v4 원문을 수정하지 않는다.

## C21. 추가 PDF 텍스트 추출 오류 보정

- 맥락: 기존 문자열 안에 OCR 오독, 빠진 표 셀, 서로 다른 박스의 문장 혼합이 남아 있었다.
- 선택지: 생성 시 철자 치환 / 기존 파일 덮어쓰기 / 원문에 근거한 누적 보정 배치와 새 보정본.
- 결정: batch-010~019를 기록하고 최종 batch-019의 유효 보정 1,504건으로 corrected-v19-a/b를 생성한다. 기존 batch-009의 408건은 그대로 보존한다. 이번 작업 중 더 정확한 영역 전사로 대체한 중간 패치는 superseded-corrections에 남긴다.
- 이유: 단순 오타뿐 아니라 셀·박스별 재전사도 있으므로 작업 명칭은 'PDF 텍스트 추출 오류 보정'으로 한다. 실제 변경과 기록의 일치 검사가 가능해야 한다.
- 관련 파일: `../corrections/batch-010/`~`batch-019/`, `../correct_extraction.py`, `../verify_corrections.py`, `../output/corrected-v19-a/`.
- 후속 검토: 보정안 작성과 PDF 대조에는 Codex를 사용했다. 고정된 보정 목록을 재실행할 때는 LLM을 호출하지 않는다. 원문 자체의 오탈자와 빠진 수치는 추정 교정하지 않는다.

## C22. 조건·절차를 실제 박스 범위로 연결

- 맥락: 다음 제목까지 같은 조건으로 묶으면 종료 지시나 다른 단계의 조건이 붙는다. 테두리가 일부 끊기면 반대로 마지막 원인 항목이 빠질 수 있다.
- 선택지: y좌표 순서로 일괄 연결 / 조건을 모두 버림 / 테두리로 제한하고 예외는 PDF에서 확인한 계약으로 처리.
- 결정: 마지막 방법을 적용한다. native 질문 141개의 조건 경계를 재검사했고 45개를 좁혔다. OCR 진단 질문에는 실제 왼쪽 박스와 같은 단계의 우측 시험 패널만 연결한다. 조건 박스 하단 14사례를 대조해 빈칸 10사례는 유지하고 나머지 4쪽은 재전사했다. 시험 카드에는 같은 카드의 Pre-Test와 NOTES를 연결한다.
- 이유: KNOWN INFO와 POSSIBLE PROBLEMS, 시험 방법, 분기 조치의 역할을 구별해야 한다. 확인한 NO 조치도 질문과 NO 표식 없이 독립적인 수리 권고로 만들지 않는다.
- 관련 파일: `prepare_nodes_v6.py`, `refine_native_v6.py`, `prepare_cards_v6.py`, `apply_end_panels_v6.py`, `rules/v6-final/box-units.jsonl`, `flow-links.jsonl`, `verify_boxes.py`.
- 후속 검토: 좌우 대응이 하나로 정해지지 않는 박스는 독립 텍스트로 남기며 조건 관계를 추정하지 않는다. 재구성 중 시험 카드가 빠지는 회귀를 막기 위해 별도 카드 목록과 결과 집합을 비교한다.

## C23. 그림을 제외하는 단위와 원문 결함

- 맥락: 텍스트 연구에서 그림을 해석한 새 설명을 추가하거나 그림과 함께 정상 본문까지 제거하면 실험 범위가 달라진다.
- 선택지: 그림 페이지 통째로 제외 / LLM 그림 설명 추가 / 그림의 관계는 PDF에 보존하고 읽을 수 있는 본문·표·박스를 유지.
- 결정: 마지막 방법. 배선·화살표·부품 위치·계기 모양은 텍스트로 설명하지 않는다. 그림 라벨과 선을 잘못 읽은 조각은 원본 위치와 제외 이유를 남긴다. 경고·독립 설명·표는 보호한다. 50쪽의 희미한 중량값은 채우지 않고 읽을 수 있는 슬링 지시만 보존한다.
- 관련 파일: `그림과_텍스트_처리원칙.md`, `prepare_scope_v6.py`, `finalize_scope_v6.py`, `rules/v6-final/figure-exclusions.jsonl`, `source-issues.jsonl`.
- 후속 검토: 그림 해석이 필요한 질의를 교범에 정답이 없는 질의와 혼동하지 않는다. 그림 관계가 PDF에만 남았다는 표시는 처리 범위가 결정된 상태다.

## C24. 정상 검토 항목의 종료와 실패 조건

- 맥락: 일반 본문 경계, OCR 블록, 흐름도 보조 문자에는 유형상 검토 표시가 붙는다. 이 수치는 실제 오류 개수와 다르다.
- 선택지: 모든 표시 일괄 삭제 / 정상 표시도 영구 보류 / 근거와 텍스트 범위를 기록한 뒤 정해진 유형만 종료.
- 결정: 마지막 방법. STRUCTURE_BOUNDARY, OCR_REGION_STRUCTURE, BOX_CONTEXT_REVIEW, FLOW_ANNOTATION_REVIEW만 원문 출처·소유 단위·판정 서명·정책 근거를 갖춘 종료 이력으로 옮긴다. 문자 선택 충돌, 서로 다른 열의 혼합, 출처 미배정, 토큰 초과는 이 규칙으로 해제할 수 없다.
- 이유: 검토 표시 정리와 오류 은폐를 구별할 수 있어야 한다. 종료된 항목도 별도 프로그램으로 원문 범위·소유 단위·판정 근거를 재검사한다.
- 관련 파일: `review_resolution.py`, `verify.py`, `rules/v6-final/review-policy.json`, `scope-resolution-record.json`, 생성본의 `review_history.jsonl`.
- 후속 검토: 미결 선택과 대체 표현의 순환 참조가 0이고 전체 감사가 PASS일 때만 실험 입력 준비 상태가 된다. 사람의 전체 문자 검수나 의미 정확성 인증을 뜻하지 않는다.

## C25. 실험 입력 버전의 고정과 재현

- 맥락: 사용자가 현재 백업, 오류 처리, 범위 확정, 검토 표시 정리 후 corpus 고정을 요청했다.
- 선택지: 기존 생성본 덮어쓰기 / 매번 OCR부터 재실행 / 원시 스냅샷·보정 목록·구조 규칙·tokenizer·코드를 함께 고정.
- 결정: 마지막 방법. 작업 전 ZIP을 보존하고 규칙은 v6-final, corpus는 별도 최종 폴더에 생성한다. 두 번의 생성 결과와 기존 v5 대비 원문 구간·변경 기록을 비교한 뒤 고정 기록과 작업 후 백업을 남긴다. 제목·조건을 포함한 500토큰 상한과 같은 단위 안의 본문 100토큰 중첩을 유지한다.
- 이유: 평가질의를 보며 corpus를 바꾸지 않고 같은 입력으로 검색 실험을 반복할 수 있어야 한다. 원시 OCR 재실행의 동일성 대신 고정한 추출 스냅샷 이후 파이프라인의 동일성을 확인한다.
- 관련 파일: `config.json`, `inputs.lock.json`, `build.py`, `compare_versions.py`, `reports/데이터_전처리_실시사항_2026-09-25.md`, `reports/rules-v6-freeze/`.
- 후속 검토: 이후 변경은 새 버전으로 만든다. 평가질의 확정, 임베딩·검색 인덱스, LLM/RAG 비교 실험은 이 고정본을 입력으로 진행한다.
