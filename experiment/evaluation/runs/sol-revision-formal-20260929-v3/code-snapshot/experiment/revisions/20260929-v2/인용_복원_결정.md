# R06. 분리된 원문 구절을 연속 인용처럼 반환한 경우

- 맥락: M18 RAG의 검색 문맥 판정에서 Sol이 같은 표의 필드들을 이어 적었다. 원문에는 중간에 `ITEM NO.: 29` 및 반복 헤더가 있어 기존 연속 문자열 검사가 세 차례 모두 거절했다. 원래 실행에는 평가기 오류와 결측을 그대로 보관한다.
- 선택지: 추가 API 호출 / 결측 유지 / 원문의 순서와 문구를 완전히 확인할 수 있는 인용만 프로그램으로 복원.
- 결정: 마지막 방법을 별도 파생 결과에 적용한다. 판정 값·주장·사유·근거 ID는 바꾸지 않는다. 인용의 각 줄이 지정된 같은 원문에 **동일 문구·동일 순서**로 존재할 때만, 생략된 중간 부분까지 원문에서 그대로 가져와 하나의 연속 구간으로 저장한다. 문자열 유사도나 LLM 보정은 사용하지 않는다.
- 제한: 적어도 두 개의 충분히 긴 구절이 일치해야 하며, 과도하게 넓은 구간은 거절한다. 단어·숫자·부정·순서가 달라 일치하지 않는 경우, 다른 근거에만 있는 경우, 누락·중복 주장 또는 인용 수 불일치는 이 방법으로 고치지 않는다. 정상 결과는 재선택하지 않는다. 최종 결측 단계에 한해 저장된 최초 복원 가능한 응답을 채택한다.
- 이유: 같은 원문 안의 명시적 인용 형식 오류를 추가 모델 판단 없이 바로잡을 수 있다. 인용만 변경한 내역과 원 응답·원 결과의 해시를 기록하므로 판정 변경과 구별할 수 있다.
- 영향: `derive_citations.py`, `sol-revision-formal-20260929-v3`, 새 결과 문서. 원 v2 실행·실패 기록·판정은 보존한다. 추가 API 호출은 없다.
- 후속: 정상/누락/숫자 변경/순서 역전/다른 출처 사례를 검사하고, 전 대상 결과에서 원 기록과 차이가 선언된 인용 복원 및 파생 점수뿐인지 확인한다. 의미 검토를 프로그램이 대신했다고 표현하지 않는다.
