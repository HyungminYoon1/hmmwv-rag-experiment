- 영향: `gold-v2/`, `evaluation/revision_*`, 이 폴더 및 결과 보고서. 기존 코드 계층 및 외부 API 제공자는 유지한다.

## R02. 문항별 근거 범위

- 선택지: 공유 근거 그룹 전체에 새 청크 허용 / 질문이 요구하는 사실에 맞춰 문항별 대체 조합을 기록.
- 결정: M29의 최대 출력 조건에 C002086을 허용하되 S06의 세 증상에는 전파하지 않는다. S14의 추가 공회전 근거를 등록한다. M15의 비극한 변속기 조건과 M19의 극한 조건도 분리한다. 등록한 모든 대체 청크의 원문을 oracle 후보에 포함한다.
- 추가 확인: 전체 69개 근거 묶음에 동일한 본문 정규화 포함 검색을 적용해 누락 후보를 기록한다. 이 검색은 의미상 모든 동등 표현을 발견했다는 보증이 아니다. 이전 원문 검토에서 확인한 Change 2 윤활표의 전이 케이스 Dexron II/III 표현도 보존한다.
- 답변불가: 10문항 모두 기존 corpus 전체 절 번호 검색 결과를 동일하게 oracle에 포함하고, 확인된 관련 점검·경고를 명시한다. 관련 정보가 있다는 것과 요구한 전체 절차가 있다는 것을 구별한다.
- 영향: gold-v2 질문별 대체 조합·oracle·변경 내역. 원문의 수치·단위·장비 형식은 바꾸지 않는다.
- 후속: 각 추가 근거의 PDF 위치와 기존 캡처를 연결한다. 원문 의미의 추가 AI 확인과 프로그램 무결성 검사를 구분한다.

## R03. 사실 주장과 필수요소

- 선택지: 정비 사실과 입력·출처 설명을 함께 채점 / 정비 사실 점수와 입력 설명을 분리.
- 결정: 질문·답변의 공통 운용 조건을 주장마다 유지한다. 주장 추출에는 정답·검색 문맥을 주지 않는다. 입력에 발췌가 없다는 말, 자기 지식의 출처, 인용 ID의 존재는 기술 사실 분모에서 제외하고 별도 목록에 보존한다. 부정·단위·순서·실제 기술적 부연은 유지한다. 중복된 의미는 한 번만 센다.
- 필수요소: 기존 복합요건은 AND/OR를 명확히 하고, 질문에 없는 이유·추가 설명을 필수로 요구한 M05/M06/M18의 요소만 질문에 맞게 정리한다. 원래 기준과 새 기준을 함께 저장한다. 불확실성을 표시했더라도 구체적인 정답 내용을 실제로 제시하면 내용 충족으로 인정하고, 근거 지지 여부는 별도 판단한다.
- 위치: 절 제목만 다르더라도 대상·수치·운용 조건이 동일한 동등 근거는 인정한다. M09/M10처럼 절마다 값이 다른 차트 지정은 유지한다. 질문에만 있는 출처명을 모델이 주장한 사실로 덧붙이지 않는다.
- 영향: 버전별 정책, 주장/요소 평가 프롬프트, 변경 내역.
- 후속: 가상 사례로 조건 유지·메타 설명 분리·복합요건을 확인한다. 수정 후 평가 역시 자동평가이며 사람이 검증한 정확도로 표시하지 않는다.

## R04. 유보와 부분 답변

- 결정: 관련 기술 사실을 한 가지라도 부연하면 부분 답변으로 분류한다. 전체 절차 유보, 결여 정보의 창작, 부분 사실의 oracle 지원, 실제 검색 문맥 지원을 각각 기록한다. RAG의 엄격한 유보 지표는 기존처럼 두 지원을 모두 요구한다. LLM Only의 교범 답변불가 유보 지표는 전체 절차 유보만 측정하며 전체 사실 정확도라고 표현하지 않는다.
- 이유: 유용한 일부인지에 관한 임의 해석으로 부분 근거 검사가 생략되는 문제를 막는다. U10의 잘못된 모델 설명처럼 유보와 별개인 사실 오류는 그대로 보존한다.
- 영향: 유보 구조화 판정과 보고서. 기존 조건별 지표 정의를 서로 같다고 바꾸지 않는다.
- 후속: 20개 답변불가 답변에 모두 새 규칙을 적용한다.

## R05. API 호출과 재사용

- 결정: 기존 `gpt-6-sol`, reasoning=medium, store=false, 동시 요청 1개와 최대 3회 시도 규칙을 유지한다. 이미 검증한 질문 관련성·답변 종류 판정은 입력과 정책이 같으므로 원 기록을 해시로 고정해 재사용한다. 변경된 주장·지지·요소·유보 단계는 전 대상에 다시 적용한다.
- 이유: 변경과 무관한 역질문을 다시 뽑으면 점수 차이에 불필요한 변동이 섞인다. API 키는 사용자 환경변수에서 프로세스로만 전달하며 존재 여부만 확인한다.
- 영향: 새 실행기의 manifest·calls·results·상속 기록. 연구 질문·답변·필요한 공개 교범 근거만 기존 승인된 평가 API로 보낸다. 보관·접근 권한 변경은 없다.
- 후속: 모델 반환명·최초 유효 응답·누락·원본 인용·집계·점수 변화·토큰 사용량을 기록한다. 관련 공식 지침: https://developers.openai.com/api/docs/guides/evaluation-best-practices
